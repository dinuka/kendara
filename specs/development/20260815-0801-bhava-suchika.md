## Implementation Notes

- **Binding rule:** `Bhava Suchika = ((navamsaSign − lagnaSign) mod 12) + 1` (whole-sign, 1–12), applied to all 9 planets (Rahu/Ketu are 8/9).
- **Auto derivation:** navamsa lagna is derived inline from the birth ascendant sign/degree via the shared movable/fixed/dual offset table (`navamsaSign`, `NAVAMSA_OFFSET = [0, 8, 4]`). A 1e-9 epsilon pins exact boundary multiples to the upper wedge (double precision: `2*(30/9)` is `1.9999999999999998`), matching UT-BS-013/015. Real ephemeris degrees never sit on boundaries.
- **Resolve rules (single behavior):** stored valid 1–12 wins; stored `null` = absent; stored corrupt (0/13/string/1.5) → undefined + `console.warn`; sparse record → missing keys undefined; only keys "1".."9" read; auto legacy fallback = recompute from stored ascendant + per-planet navamsaSign; manual fallback = entered `navamsaLagna` / `navamsaHouses` D9-house sign map (never `planets[].navamsaSign`, which falls back to birth sign in synthesized planets); manual without navamsa → undefined (D5 gate).
- **Recalculation:** auto branch persists via `...calculated`; manual branch via `...synth` — no merge for Bhava Suchika, no `overridden` keys ever.
- **Search:** name match wins (merged SI+EN maps, case/diacritic-insensitive); else trigger word + number 1–12. Multi-planet query pairs with the FIRST matched planet. Exact mode `exact_bhava_suchika` / `exact_planet_bhava_suchika`; typed conditions live under `queryUnderstanding.exactMatch` (deeply nested), `conditions` are keyword strings.
- **Verification:** 90/90 new tests pass; full suite 719 passed / 11 failed — the 11 failures (`privacy.test.ts` `req.nextUrl` setup, `search-combined.test.ts` pre-rule assertions) were reproduced identically at HEAD with the feature stashed, i.e. pre-existing and unrelated. `pnpm build` clean. `pnpm lint` crashes at config load (`eslint-plugin-react@7.37.5` vs `eslint@10.7.0` flat-config incompatibility) — pre-existing toolchain issue, affects all files.

## Deviations

- Function signatures differ from the architecture spec's suggested variants (single compute module; `resolveLagnaBhavaSuchika(calculatedDetails: unknown)` / `resolvePlanetBhavaSuchika(calculatedDetails: unknown, planetName: number)` — `unknown`-typed per repo convention of reading lean Mongoose docs).
- Schema uses `Mixed` with no default (architecture proposed `Map default {}`): avoids ghost keys for manual-without-navamsa and null-normalization surprises.
- D5-gating resolution follows the user-story wording over the architecture snippet (which contained an unbounded `navamsaHouses` truthiness bug).
- `computeNavamsaLagnaSign` uses the shared offset table + epsilon (see notes) instead of the spec's floor-down boundary behavior.
- Multi-planet bhava-suchika clauses pair with the first matched planet (single value per condition).
- Search card tag tooltip is CSS-only and may clip inside the `overflow-y-auto` results container; `title` attribute provides the fallback.
