# User Stories — භාව සුචික නවාංශක ක්‍රමය (Bhava Suchika Navamsa / House Index)

**Date:** 2026-08-14
**Source:** `docs/bhava-suchika.md`
**Status:** Draft
**Related:** `20260813-1954-shadbalaya.md` (precedent: derived per-planet values in the calculations tab persisted on `CalculatedDetails`); `docs/done/ascendant-wargoththama-tags.md` (the Lagna section and its tags); `docs/done/yogakaraka.md` (precedent: computed value stored as numeric arrays on `CalculatedDetails`)

## Background / Context

The calculations tab of the horoscope detail page shows an Ascendant (Lagna) section with derived tags (Wargoththama, Gandantha/Gandamula, Pushkara) and a derived planets table (Planet, Sign, Str, House, Conjunctions, Aspects, Other). This feature adds the **භාව සුචික නවාංශක ක්‍රමය (Bhava Suchika Navamsa method)** — a "house index" computed from the Navamsa (D9) chart:

- **What it is:** for a point (the Lagna or a planet), take the point's Navamsa sign, find which house that sign occupies in the Lagna (D1) chart — that house number (1-12) is the point's Bhava Suchika.
- **Lagna:** use the sign of the 1st house of the Navamsa chart (the Navamsa Lagna), then map to the D1 house.
- **Planets:** use the planet's sign in the Navamsa chart, then map to the D1 house.
- **Display:** the value shows in the Lagna section alongside Wargoththama/Gandamula, and as a new column in the planets table in the calculation tab.
- **The 12 names** (authoritative Sinhala from the feature document):

| Value | Sinhala name |
|-------|--------------|
| 1 | ලග්නාංශකය |
| 2 | ධනාංශකය |
| 3 | වික්‍රමාංශකය |
| 4 | සුඛාංශකය |
| 5 | පූර්වපුන්‍යාංශකය |
| 6 | ශෂ්ඨාංශකය |
| 7 | සප්තමාංශකය |
| 8 | නිධානාංශකය |
| 9 | භාග්‍යාංශකය |
| 10 | අභිමානාංශකය |
| 11 | ලාභාංශකය |
| 12 | ව්‍යාංශකය |

Storage lives on `CalculatedDetails` as `lagnaBhavaSuchika` (Integer 1-12) and `bhavaSuchika` (Record keyed by numeric Planet enum string `"1"`…`"9"`, values 1-12) — see `data-model.md` → [Bhava Suchika (House Index)](#) structure. Following the `yogakaraka`/`maranakaraka`/`wargoththamaPlanets` precedent, the values are **computed at calculation time and persisted**, then recomputed by the AstrologySettings full recalculation job. Unlike Shad Bala there are **no user overrides** — the value is purely derived and read-only.

## Bhava Suchika Actors

### Student

- **Description**: An astrology student who studies the Navamsa-derived house index of each point.
- **Bhava-Suchika-Specific Goals**: See the Bhava Suchika of the Lagna and of each planet to analyse how each point's Navamsa sign lands in the birth chart.
- **Bhava-Suchika-Specific Permissions**:
    - View the Lagna's භාව සුචික value in the Lagna section of the calculation details (alongside Wargoththama/Gandamula)
    - View each planet's භාව සුචික value in a dedicated column of the planets table in the calculation tab
    - View the values in Sinhala or English
    - View the values read-only (no editing) on own, public and share-linked horoscopes
    - On manual horoscopes, view the values only when Navamsa data has been entered (omitted otherwise)

### System (Calculation Engine)

- **Description**: Automated services that compute and persist the Bhava Suchika values.
- **Bhava-Suchika-Specific Responsibilities**:
    - Compute `lagnaBhavaSuchika` — the D1 house of the Navamsa Lagna sign — and `bhavaSuchika[planet]` — the D1 house of each planet's Navamsa sign — for `source: "auto"` horoscopes from the calculated D1 houses and per-planet Navamsa signs
    - Compute the same values for `source: "manual"` horoscopes from the entered `manualHousePlacements` D1 house signs and the entered Navamsa data (`navamsaLagna` / `navamsaHouses`)
    - Persist the values on `CalculatedDetails` and recompute them on the AstrologySettings full recalculation job (no overrides — always recomputed)
    - Provide a render-time pure-function fallback so legacy documents missing the fields still render correct values

### US-BS-001: Bhava Suchika in the Lagna section

- **Title**: Student views the Lagna's භාව සුචික alongside Wargoththama and Gandamula
- **Story**: As a student, I want to see the Lagna's භාව සුචික (Bhava Suchika) value in the Lagna section, so that I can see the Navamsa-derived house index of the Lagna together with the other Lagna indicators.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: US-BS-003 (Lagna calculation), US-BS-005 (i18n names)

#### Acceptance Criteria

1. **Lagna Section Placement**:
    - The Ascendant (Lagna) section of the calculation details renders the Bhava Suchika value alongside the existing Wargoththama, Gandantha/Gandamula and Pushkara indicators
    - The value is labeled in the active locale (e.g. "භාව සුචික" / "Bhava Suchika") and shows the named house index (e.g. "සප්තමාංශකය")

2. **Value Rendering**:
    - Given a horoscope whose Lagna Bhava Suchika is 7, When the Lagna section renders, Then the value 7 with the name සප්තමාංශකය is displayed
    - The displayed name resolves from the stored numeric value (1-12) via i18n — no localized text is stored

3. **Both chart sources**:
    - The value renders for both `source: "auto"` and `source: "manual"` horoscopes (manual only when Navamsa data has been entered — see US-BS-006)

4. **Read-only**:
    - The value is display-only — no editing, toggling or override UI exists (unlike the Shad Bala checkboxes)

#### Edge Cases

- **Legacy document without the field**: the value is derived at render time from the stored `ascendant` and `houses` (render-time fallback) so old horoscopes still render correctly
- **Manual horoscope without Navamsa data**: the value is omitted (the Lagna section renders the other indicators as usual)

#### Business Rules

- The Lagna Bhava Suchika is a pure derived value — never user-editable
- Display uses i18n message keys; no hardcoded Sinhala/English strings in code

### US-BS-002: Bhava Suchika column in the planets table

- **Title**: Student views each planet's භාව සුචික in a dedicated column of the planets table
- **Story**: As a student, I want a dedicated භාව සුචික (Bhava Suchika) column in the planets table of the calculation tab, so that I can see the Navamsa-derived house index of every planet in one glance.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: US-BS-004 (per-planet calculation), US-BS-005 (i18n names)

#### Acceptance Criteria

1. **New Column**:
    - The planets table in the calculation tab gains a new column labeled "භාව සුචික" (Bhava Suchika)
    - The column is distinct from the existing "Other" column (which holds Wargoththama, Yogakaraka etc.) — the doc explicitly calls for a new column

2. **Per-Planet Values**:
    - The table has 9 rows (රවි/Sun, සඳු/Moon, කුජ/Mars, බුධ/Mercury, ගුරු/Jupiter, සිකුරු/Venus, ශනි/Saturn, රාහු/Rahu, කේතු/Ketu) and every row shows that planet's Bhava Suchika (1-12) with its named form (e.g. "7 — සප්තමාංශකය")
    - Rahu and Ketu have values too — they are points with Navamsa signs like any other planet

3. **Both chart sources**:
    - The column renders for both `source: "auto"` and `source: "manual"` horoscopes (manual only when Navamsa data has been entered — see US-BS-006)

4. **Read-only**:
    - The column is display-only — no per-cell editing exists

#### Edge Cases

- **Legacy document without the field**: values are derived at render time from the stored per-planet Navamsa sign and `houses`
- **Manual horoscope without Navamsa data**: the column is rendered empty (or the values are shown as "—") — mirroring how the existing Navamsa/Navamsa-Strength enrichment of the planets table behaves without entered Navamsa data
- **Values not unique**: two planets can share the same Bhava Suchika value — each cell shows its own value (no deduplication or grouping)

#### Business Rules

- The column is rendered from `CalculatedDetails.bhavaSuchika` (Record keyed by numeric Planet enum string); absent entries default to a blank/placeholder cell
- Display uses i18n message keys — no hardcoded strings

### US-BS-003: Lagna's Bhava Suchika calculation

- **Title**: System computes the Lagna's Bhava Suchika from the Navamsa Lagna sign mapped into the D1 houses
- **Story**: As a student, I want the system to compute the Lagna's භාව සුචික as the D1 house that the Navamsa Lagna sign occupies, so that the Lagna value follows the Navamsa method exactly.
- **Priority**: High
- **Actor**: System
- **Dependencies**: D1 lagna sign, D1 house signs, Navamsa Lagna sign (auto: D9 ascendant sign; manual: entered `navamsaLagna`)

#### Acceptance Criteria

1. **Rule applied**:
    - Given a horoscope with D1 Lagna sign Mesha (1) and Navamsa Lagna sign Vrishabha (2), When the Lagna Bhava Suchika is computed, Then the value is 2 (sign 2 occupies house 2 of a Mesha-lagna chart → ධනාංශකය)
    - Given a horoscope with D1 Lagna sign Mesha (1) and Navamsa Lagna sign Makara (10), Then the value is 10 (→ අභිමානාංශකය)

2. **Same sign → house 1**:
    - Given a horoscope whose Navamsa Lagna sign equals the D1 Lagna sign, When computed, Then the value is 1 (ලග්නාංශකය)

3. **Wrap-around**:
    - Given a Mesha (1) lagna chart whose Navamsa Lagna sign is Meena (12), When computed, Then the value is 12 (ව්‍යාංශකය) — the mod-12 mapping wraps correctly

4. **Both chart sources**:
    - The rule applies identically to `source: "auto"` horoscopes (D9 ascendant sign) and `source: "manual"` horoscopes (entered `navamsaLagna`)

#### Edge Cases

- **House lookup by sign**: the house of a sign is the D1 house whose whole-sign `sign` equals the Navamsa Lagna sign — equivalently `((navamsaLagnaSign − lagnaSign) mod 12) + 1` (whole-sign counting; cusp-split signs are handled by the whole-sign assignment — see Open Questions)
- **Manual horoscope without Navamsa data**: the Lagna value is not computed (see US-BS-006)

#### Business Rules

- `lagnaBhavaSuchika` ∈ [1, 12]; always an integer
- The computation is deterministic and pure — no ephemeris dependency beyond the already-stored D1/D9 inputs

### US-BS-004: Per-planet Bhava Suchika calculation

- **Title**: System computes each planet's Bhava Suchika from its Navamsa sign mapped into the D1 houses
- **Story**: As a student, I want the system to compute each planet's භාව සුචික as the D1 house that the planet's Navamsa sign occupies, so that the per-planet values follow the Navamsa method exactly.
- **Priority**: High
- **Actor**: System
- **Dependencies**: per-planet Navamsa signs (auto: `planet.navamsaSign`; manual: derived from entered Navamsa chart), D1 house signs

#### Acceptance Criteria

1. **Rule applied**:
    - Given a Mesha (1) lagna chart where a planet's Navamsa sign is Makara (10), When the planet's Bhava Suchika is computed, Then the value is 10 (→ අභිමානාංශකය)
    - Given a Mesha (1) lagna chart where a planet's Navamsa sign is Kanya (6), Then the value is 6 (→ ශෂ්ඨාංශකය)

2. **All nine planets**:
    - Given any horoscope, When the planets table is computed, Then all 9 planets (including Rahu and Ketu) receive a Bhava Suchika value in 1-12, each derived from that planet's own Navamsa sign

3. **Wargoththama planet**:
    - Given a planet whose birth sign equals its Navamsa sign (Wargoththama), When computed, Then its Bhava Suchika equals its D1 house (e.g. a Wargoththama planet in the 7th house sign has value 7 — සප්තමාංශකය)

4. **Both chart sources**:
    - The rule applies identically to `source: "auto"` horoscopes (computed Navamsa sign per planet) and `source: "manual"` horoscopes (Navamsa sign derived from the entered Navamsa chart)

#### Edge Cases

- **Manual horoscope without Navamsa placements**: per-planet values are not computed (see US-BS-006)
- **Multiple planets sharing a value**: no special handling — each planet cell shows its own derived value

#### Business Rules

- `bhavaSuchika[planet]` ∈ [1, 12] for every planet key `"1"`…`"9"` when computed
- The computation is deterministic and pure — no ephemeris dependency beyond the already-stored inputs

### US-BS-006: Manual horoscope behaviour

- **Title**: Bhava Suchika on manual horoscopes — requires entered Navamsa data
- **Story**: As a student working with a manually-entered horoscope, I want the system to compute Bhava Suchika values only from the Navamsa data I have entered, so that the values reflect the available input.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-BS-003, US-BS-004; `manualHousePlacements` (`navamsaLagna` / `navamsaHouses`)

#### Acceptance Criteria

1. **Lagna value from entered Navamsa Lagna**:
    - Given a manual horoscope with an entered `navamsaLagna`, When the Lagna Bhava Suchika is computed, Then it uses the entered Navamsa Lagna sign mapped into the entered D1 house signs

2. **Per-planet values from entered Navamsa chart**:
    - Given a manual horoscope with entered Navamsa house placements, When the per-planet values are computed, Then each planet's Navamsa sign is derived from the entered Navamsa chart and mapped into the entered D1 house signs

3. **No Navamsa data → omitted**:
    - Given a manual horoscope with no entered Navamsa data (no `navamsaLagna`, no `navamsaHouses`), When the Lagna section and planets table render, Then the Bhava Suchika values are omitted (blank cell / no tag), mirroring the existing navamsa enrichment behaviour of the planets table

4. **Partially entered Navamsa data**:
    - Given a manual horoscope where only some Navamsa data is present, Then the values that can be derived are shown and the rest are omitted (exact partial-input matrix — see Open Questions)

#### Business Rules

- `manualHousePlacements` remains the single source of truth for the manual chart; Bhava Suchika is derived from it and never stored independently of the derivation inputs

### US-BS-007: Storage, recalculation and legacy documents

- **Title**: Bhava Suchika values persist, survive recalculation and have a render-time fallback
- **Story**: As a student, I want the Bhava Suchika values to be stored with the horoscope and to remain correct after a full recalculation, so that the feature works consistently across sessions and system changes.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-BS-003, US-BS-004; `AstrologySettings` recalculation job (`20260812-2111-system-astrology-settings.md`)

#### Acceptance Criteria

1. **Persisted on CalculatedDetails**:
    - Given a computed horoscope (auto or manual), When it is saved, Then `lagnaBhavaSuchika` (Integer 1-12) and `bhavaSuchika` (Record keyed by planet enum string) are stored on `CalculatedDetails`

2. **Recomputed on full recalculation**:
    - Given the AstrologySettings full recalculation job runs, When it processes a horoscope, Then the Bhava Suchika values are recomputed from the current chart data (auto: re-run from birth details; manual: re-derived from `manualHousePlacements`) — there are no `overridden` flags to preserve, unlike Shad Bala

3. **Legacy render-time fallback**:
    - Given a horoscope stored before the fields existed, When the Lagna section or planets table renders, Then the values are derived at render time from the always-stored `ascendant`, `houses` and per-planet Navamsa signs (auto) or entered Navamsa data (manual), so legacy documents still render correct values

4. **Read-only on all views**:
    - The values are display-only on own horoscopes, public horoscopes and share links — no mutation endpoint is introduced

#### Business Rules

- Bhava Suchika is a pure derived value: stored for performance/consistency, recomputed on recalculation, and derivable at render time as a fallback — no user-editable state exists

### US-BS-008: Bhava Suchika in search queries and search results

- **Title**: Students can find horoscopes by Bhava Suchika and see the values in search results
- **Story**: As a student, I want to search for horoscopes by Bhava Suchika (the Lagna's or any planet's house index, by name or number) and see the values mirrored in the search results, so that the feature is usable from the search experience, not only the calculation tab.
- **Priority**: High
- **Actor**: Student, System
- **Dependencies**: US-BS-001, US-BS-002, US-BS-003, US-BS-004, US-BS-005; search pipeline (`src/app/api/search/route.ts`, `src/lib/search/textContent.ts`)

#### Acceptance Criteria

1. **Query by Lagna Bhava Suchika**:
    - Given a search query containing a Bhava Suchika trigger and/or house-index name (e.g. "භාව සුචික ලග්නාංශකය", "bhava suchika bhagyamshaka", "ලග්නාංශකය"), When the search runs, Then horoscopes whose Lagna Bhava Suchika equals that house index are returned and ranked above non-matches

2. **Query by per-planet Bhava Suchika**:
    - Given a search query pairing a planet with a Bhava Suchika value (e.g. "ගුරු භාව සුචික 11", "Jupiter bhava suchika labhamshaka"), When the search runs, Then horoscopes where that planet's Bhava Suchika equals the value are returned (mirroring the existing planet-strength pairing behaviour)

3. **Search result cards show the values**:
    - Given a search result card, When it renders, Then the Lagna section shows the Bhava Suchika tag alongside the existing flags, and each planet row shows the per-planet value in the same position/format as the calculation tab

4. **Bilingual query terms**:
    - Both the Sinhala and English house-index names (US-BS-005) and the trigger words ("භාව සුචික" / "bhava suchika") are recognised in queries

5. **Vector search coverage**:
    - The horoscope search text content includes the Bhava Suchika values in both languages (SI + EN), so vector/embedding search also surfaces Bhava Suchika matches

6. **Legacy and manual charts**:
    - Horoscopes without computable values (manual charts without entered Navamsa data) simply do not match a Bhava Suchika query and their search cards do not show the values

#### Edge Cases

- **No trigger word, bare house-index name**: a query that is just "භාග්‍යාංශකය" / "bhagyamshaka" should still match horoscopes with that Lagna value (the house-index name alone is a sufficient signal)
- **Number form**: a query like "bhava suchika 9" or "භාව සුචික 9" matches house index 9
- **Multiple values**: comma-AND groups and හෝ OR clauses behave like the rest of the search grammar

#### Business Rules

- Matching reuses the existing search grammar (keyword + exact-match + scoring + vector) — no new search UI, no new route
- The same numeric house-index values feed search; display names resolve through i18n

## Clarifying Assumptions

1. **The calculation rule** is: `Bhava Suchika = house of the point's Navamsa sign in the D1 chart`, using whole-sign house assignment — for the Lagna the Navamsa sign is the sign of the 1st house of the Navamsa chart; for a planet it is the planet's Navamsa sign. Equivalently `((navamsaSign − lagnaSign) mod 12) + 1`.
2. **All 9 planets** (including Rahu/Ketu) receive a Bhava Suchika value — nodes are points with Navamsa signs like any other planet.
3. **Stored, not computed-only**: following the `yogakaraka`/`maranakaraka`/`wargoththamaPlanets` precedent, values are computed at calculation time and persisted on `CalculatedDetails` (`lagnaBhavaSuchika` + `bhavaSuchika`), recomputed by the AstrologySettings recalculation job, with a render-time pure-function fallback for legacy documents (mirroring `computeAscendantSpecialFlags`).
4. **No overrides**: unlike Shad Bala checkboxes, Bhava Suchika is display-only — there is no editing, toggling or override persistence.
5. **Numeric-enum conventions** apply throughout: planets are numeric `Planet` (1-9), signs are numeric `ZodiacSign`, houses are 1-12; the Bhava Suchika value is the numeric house index 1-12 and its display name is resolved via i18n per locale.
6. **Manual horoscopes** need entered Navamsa data (`navamsaLagna` for the Lagna value; Navamsa house placements for the per-planet values); without it the values are omitted, mirroring the existing Navamsa enrichment behaviour of the planets table.
7. **The Sinhala names are authoritative** (from `docs/bhava-suchika.md`); the English names are proposed transliterations pending domain confirmation.

## Open Questions

1. **English names for the 12 house-index names** — `docs/bhava-suchika.md` provides Sinhala names only. Proposed English transliterations (Lagnamshaka, Dhanamshaka, Vikramamshaka, Sukhamshaka, Purvapunyamshaka, Shashthamshaka, Saptamamshaka, Nidhanamshaka, Bhagyamshaka, Abhimanamshaka, Labhamshaka, Vyamshaka) are listed in `data-model.md` — confirm or provide authoritative English labels. (PM/Domain)
2. **Whole-sign vs cusp-split house mapping** — "the house of that sign in the Lagna chart" is assumed to use the whole-sign house assignment (`houses[].sign`); on auto charts with unequal house cusps a sign could theoretically straddle two houses. Confirm whole-sign is always intended (as assumed) or whether cusp boundaries should decide. (Domain)
