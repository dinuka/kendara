# User Stories — ෂඩ් බලය (Shad Bala / Six Strengths)

**Status:** Draft
**Related:** `20260812-2111-system-astrology-settings.md` (AstrologySettings full recalculation — overrides must survive it); `docs/done/maranakaraka.md` + `src/lib/astrology.ts` `computeMaranakaraka` (Naisargika bala input); `src/lib/astrologyEnums.ts` (numeric Planet/ZodiacSign/PlanetaryStrength enums)

## Background / Context

The calculations tab of the horoscope detail page shows a derived planets table, houses, dashas and other calculated values. This feature adds a **ෂඩ් බලය (Shad Bala)** table — the six classical strengths of each planet:

| Bala | Sinhala | Meaning |
|------|---------|---------|
| Sthana | ස්ථාන බල | Positional strength (exaltation / debilitation / enmity) |
| Cheshta | චේෂ්ටා බලය | Motivational / motion strength (retrograde, paksha, Uttarayana, planet war) |
| Kala | කාල බලය | Temporal strength (day/night, lunar paksha, varga loads) |
| Dig | දිග් බලය | Directional strength (planet in its directional house) |
| Drishti | දෘෂ්ඨි බලය | Aspect strength — **manually entered only**, the system cannot calculate it |
| Naisargika | නෛසර්ගික බලය | Natural strength — absent only for the Maranakaraka planets |

The table has **8 columns**: ග්රහයා (Planet), the six bala columns, and අනුපාතය (Anupatha ratio) shown as `(n/6)` — the count of checked balas over 6, **not** a division result.

Each bala renders as a **checkbox** (checked = planet has the bala). Checkboxes are auto-checked from the rules below where the system can calculate them; the student may **check/uncheck any bala** and the change **auto-saves**. Every checkbox has a **tooltip** explaining why it is checked or unchecked (e.g. Sthana "Uchcha", Kala "Because of conjunction with Shukla Chandra"). User overrides persist and are **never wiped** by the AstrologySettings recalculation job.

Rules summary from the feature document:

- **Sthana bala**: the planet loses it in a Shatru (enemy sign) placement — whether alone or combined with Neecha (the Neecha-and-Shatru combination uses the dedicated `neecheShatru` reason). A planet that is Neecha but NOT in an enemy sign keeps the bala.
- **Cheshta bala**: Ravi in Uttarayana (auto horoscopes with birth time + location; manual fallback = Ravi in Makara/Kumba/Meena/Mesha/Wrushaba); Moon in Shukla paksha; Kuja/Buda/Sikuru/Guru/Shani combined with a Shukla-paksha Chandra; any Vakra (retrograde) planet; a planet that wins a planet war keeps the bala until 48h after the war (auto only; manual = student updates manually).
- **Kala bala**: any one condition suffices — Chandra/Kuja/Shani for a night birth; Ravi/Guru/Sikuru for a day birth (Ravi's day condition is suppressed while Moon is in Shukla paksha); Budha/Guru/Sikuru/Rahu when Moon is in Shukla paksha; Kuja/Shani/Rahu when Moon is in Krushna paksha (Ravi is not in the Krushna list — his only Kala source is a Krushna-paksha day birth); plus planets carrying Hora/Panchama/Sukshama varga loads (not calculable for manual horoscopes).
- **Dig bala**: Guru/Budha → 1st house; Kuja/Ravi → 10th house; Chandra/Shukra → 4th house; Shani → 7th house. Rahu/Ketu have no mapping.
- **Naisargika bala**: present unless the planet is a Maranakaraka — the planet that occupies its designated death house (Chandra in the 8th, Rahu in the 9th, Shani in the 1st, Ravi in the 5th, Shukra in the 6th, Kuja in the 7th, Budha in the 4th, Guru in the 3rd; lagna/rasi chart only, never D9). Multiple planets can qualify.
- **Drishti bala**: manual only — the system cannot calculate it.

Storage lives on `CalculatedDetails.shadbalaya` (see `data-model.md` → [ShadBalaya](#) structure): keyed by numeric Planet enum, each bala stores `value`, `overridden` (user toggle — preserved across recalculation), and `reasons` (i18n keys + numeric enum params, never localized text).

## Shad Bala Actors

### Student

- **Description**: An astrology student who studies horoscopes and corrects balas the system cannot derive.
- **Shad-Bala-Specific Goals**: See all six balas per planet, understand why each is checked/unchecked, and correct the ones the system cannot calculate.
- **Shad-Bala-Specific Permissions**:
    - View the ෂඩ් බලය table (8 columns) in the calculations tab on both auto and manual horoscopes
    - Check/uncheck any bala checkbox on own horoscopes with automatic save
    - View tooltip reasons for checked and unchecked states (Sinhala and English)
    - Override balas the system cannot calculate (Drishti always; Cheshta Uttarayana/planet-war states and Kala varga loads on manual horoscopes)
    - Keep overrides after an AstrologySettings full recalculation
    - View the table read-only (no checkboxes) on non-owned horoscopes and share links

### System (Calculation Engine)

- **Description**: Automated services that compute the six balas and persist the table.
- **Shad-Bala-Specific Responsibilities**:
    - Compute Sthana, Cheshta, Kala, Dig and Naisargika balas for `source: "auto"` horoscopes; compute the derivable subset for `source: "manual"` horoscopes
    - Leave Drishti bala unset (manual only) on both sources
    - Compose tooltip reasons from i18n keys + numeric enum fields — never store localized text
    - Persist `CalculatedDetails.shadbalaya` and preserve `overridden` values across the AstrologySettings recalculation job

### US-SB-001: Shad Bala table with eight columns

- **Title**: Student views the ෂඩ් බලය table in the calculations tab
- **Story**: As a student, I want a ෂඩ් බලය (Shad Bala) table in the calculations tab of the horoscope detail page, so that I can see all six balas and the ratio for every planet in one place.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: None (new section in the existing calculations tab)

#### Acceptance Criteria

1. **Table Location**:
    - The calculations tab renders a table labeled "ෂඩ් බලය" (Shad Bala)
    - The table appears for both `source: "auto"` and `source: "manual"` horoscopes

2. **Columns**:
    - The table has exactly 8 columns in order: ග්රහයා (Planet), ස්ථාන බල (Sthana), චේෂ්ටා බලය (Cheshta), කාල බලය (Kala), දිග් බලය (Dig), දෘෂ්ඨි බලය (Drishti), නෛසර්ගික බලය (Naisargika), අනුපාතය (Anupatha ratio)

3. **Rows**:
    - One row per planet: රවි (Sun), සඳු (Moon), කුජ (Mars), බුධ (Mercury), ගුරු (Jupiter), සිකුරු (Venus), ශනි (Saturn), රාහු (Rahu), කේතු (Ketu) — 9 rows total
    - The Planet cell shows the planet name in the active locale (numeric Planet enum resolved via i18n labels)

4. **Bala Cells**:
    - Each of the six bala columns renders a checkbox per planet (checked = has the bala)
    - The අනුපාතය column renders the ratio as `(n/6)` (see US-SB-010)

#### Edge Cases

- **Empty/unset bala**: a bala the system has not computed and the student has not toggled renders as an unchecked checkbox with the manual/set-manually tooltip (e.g. Drishti on a fresh horoscope)

#### Business Rules

- The table is rendered from `CalculatedDetails.shadbalaya`; absent balas default to unchecked
- Display uses i18n message keys — no hardcoded Sinhala/English strings in code

### US-SB-002: Sthana bala (ස්ථාන බල)

- **Title**: System computes Sthana bala — present unless the planet is in a Shatru (enemy) sign
- **Story**: As a student, I want Sthana bala to be checked for a planet unless it is in a Shatru (enemy) sign (including the Neecha-and-Shatru combination), so that the positional strength reflects the true classical rule.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-SB-001 (table), planetary strength data (`PlanetaryStrength` enum in `src/lib/astrologyEnums.ts`)

#### Acceptance Criteria

1. **Neecha AND Shatru → no bala**:
    - Given a planet in a Neecha sign with a Shatru strength, When the table loads, Then its Sthana checkbox is unchecked and the tooltip explains the Neecha + Shatru combination (e.g. `shadbalaya.sthana.reason.neecheShatru` with strength and sign params)

2. **Only Neecha (not Shatru) → has bala**:
    - Given a planet that is Neecha but Sama/Mitra/Own-sign (not Shatru), When the table loads, Then its Sthana checkbox is checked

3. **Only Shatru (not Neecha) → no bala**:
    - Given a planet in a Shatru (enemy) sign that is not Neecha, When the table loads, Then its Sthana checkbox is unchecked with the `shadbalaya.sthana.reason.shatru` reason

4. **Uchcha and other strengths → has bala**:
    - Given a planet in Uchcha, Athi Uchcha, Own Sign or Moolatrikona, When the table loads, Then its Sthana checkbox is checked with the corresponding reason (e.g. "Uchcha" for `shadbalaya.sthana.reason.uchcha`)

5. **Both chart sources**:
    - The rule applies to both `source: "auto"` and `source: "manual"` horoscopes (manual uses the entered house/sign and its derived strength)

#### Business Rules

- A planet in a Shatru (enemy) sign has no Sthana bala; the Neecha-and-Shatru combination uses the dedicated `neecheShatru` reason
- A planet that is Neecha but in a friendly/neutral sign still keeps Sthana bala (checked with the `debilitated` reason)
- Uses the numeric `PlanetaryStrength` values: Neecha = `-1`/`-1.25`, Shatru = `-0.1`

### US-SB-003: Cheshta bala (චේෂ්ටා බලය)

- **Title**: System computes Cheshta bala from motion, paksha and planet-war conditions
- **Story**: As a student, I want Cheshta bala to be checked automatically from its classical conditions (Uttarayana, Shukla paksha, Shukla-Chandra conjunction, retrograde, planet war), so that I can see which planets are energised by movement.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-SB-001; birth time/location data (auto); planet retrograde/planet-war data

#### Acceptance Criteria

1. **Ravi in Uttarayana**:
    - Given an auto horoscope with birth time and location where Ravi is in Uttarayana, When the table loads, Then Ravi's Cheshta checkbox is checked with the Uttarayana reason
    - Given an auto horoscope where Ravi is in Dakshinayana, Then Ravi's Cheshta checkbox is unchecked for this condition

2. **Moon in Shukla paksha**:
    - Given Moon in Shukla paksha (thithi 1-15), When the table loads, Then Moon's Cheshta checkbox is checked with the Shukla-paksha reason

3. **Conjunction with Shukla-paksha Chandra**:
    - Given Kuja, Buda, Sikuru, Guru or Shani combined with a Shukla-paksha Chandra, When the table loads, Then that planet's Cheshta checkbox is checked with a conjunction reason (e.g. "Because of conjunction with Shukla Chandra")
    - Rahu/Ketu are **not** eligible for this condition

4. **Vakra (retrograde)**:
    - Given a planet marked Vakra, When the table loads, Then its Cheshta checkbox is checked with the retrograde reason
    - Rahu/Ketu are retrograde **by nature** — their usual retrograde state is NOT Vakra and gives no Cheshta bala. Only when a node is in the opposite (direct) motion is it considered Vakra

5. **Planet war winner**:
    - Given an auto horoscope where a planet wins a planet war, When the table loads, Then the winner's Cheshta checkbox is checked
    - The bala holds until 48 hours after the war ends; beyond 48h the checkbox returns to its other-condition state

6. **Any one condition suffices**:
    - A planet needs only one of the above to be checked; when several apply, the tooltip lists every reason (US-SB-009)

#### Business Rules

- Uttarayana and planet-war conditions are `source: "auto"` only (need birth time + location)
- For `source: "manual"`, the Uttarayana condition is replaced by the sign-based rule — Ravi in Makara/Kumba/Meena/Mesha/Wrushaba → checked; the planet-war condition is not computed (student sets it manually, US-SB-012)
- Rahu/Ketu: natural retrograde → not Vakra (no Cheshta bala); direct motion → Vakra. Shukla-Chandra conjunction excludes Rahu/Ketu

### US-SB-004: Kala bala (කාල බලය)

- **Title**: System computes Kala bala from day/night, paksha and varga-load conditions
- **Story**: As a student, I want Kala bala to be checked when any qualifying temporal condition holds, so that the temporal strength reflects time-of-birth, the lunar paksha and the varga loads.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-SB-001; birth time (day/night), thithi/paksha data, varga load data

#### Acceptance Criteria

1. **Night birth**:
    - Given a night birth, When the table loads, Then Chandra, Kuja and Shani Kala checkboxes are checked with the night reason

2. **Day birth**:
    - Given a day birth, When the table loads, Then Ravi, Guru and Sikuru Kala checkboxes are checked with the day reason

3. **Shukla paksha**:
    - Given Moon in Shukla paksha, When the table loads, Then Budha, Guru, Sikuru and Rahu Kala checkboxes are checked with the Shukla-paksha reason
    - Given Moon in Shukla paksha, Then Ravi has **no** Kala bala — not even when it is a day birth (the Ravi day condition is suppressed during Shukla paksha)

4. **Krushna paksha**:
    - Given Moon in Krushna paksha, When the table loads, Then Kuja, Shani and Rahu Kala checkboxes are checked with the Krushna-paksha reason
    - Given Moon in Krushna paksha, Then Ravi has **no** Kala bala from the Krushna condition (Ravi's only Kala source is a day birth during Krushna paksha)

5. **Varga loads**:
    - Given an auto horoscope, When Hora/Panchama/Sukshama varga loads are calculated, Then each planet carrying a load has its Kala checkbox checked with the varga-load reason

6. **Any one condition suffices**:
    - A planet checked under any single condition is checked — there is no requirement to satisfy all conditions

#### Business Rules

- The Hora/Panchama/Sukshama varga-load calculation is `source: "auto"` only — it cannot be calculated for manual horoscopes (open question: exact load formula — see Open Questions)
- Day/night depends on birth time and location (sunrise/sunset); for manual horoscopes without birth time the day/night conditions cannot be derived (see US-SB-012 and Open Questions)
- Shukla paksha: Budha/Guru/Sikuru/Rahu are checked; Ravi is never checked during Shukla paksha (its day condition is suppressed while Moon is in Shukla paksha)
- Krushna paksha: Kuja/Shani/Rahu are checked; Ravi is never checked from the Krushna condition

### US-SB-005: Dig bala (දිග් බලය)

- **Title**: System computes Dig bala from each planet's directional house
- **Story**: As a student, I want Dig bala to be checked when a planet occupies its directional house, so that the directional strength reflects the classical house mapping.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-SB-001; house placement data

#### Acceptance Criteria

1. **Directional houses**:
    - Given Guru or Budha in the 1st house, When the table loads, Then its Dig checkbox is checked with the 1st-house reason
    - Given Kuja or Ravi in the 10th house, Then its Dig checkbox is checked with the 10th-house reason
    - Given Chandra or Shukra in the 4th house, Then its Dig checkbox is checked with the 4th-house reason
    - Given Shani in the 7th house, Then its Dig checkbox is checked with the 7th-house reason

2. **Other houses**:
    - Given any of these planets in any other house, Then its Dig checkbox is unchecked

3. **Rahu / Ketu**:
    - Given Rahu or Ketu in any house, Then its Dig checkbox is always unchecked (no directional mapping exists)

4. **Both chart sources**:
    - The house used is the cusp-based calculated house on auto charts and the entered house on manual charts

#### Business Rules

- Dig bala rule is fixed and identical for every horoscope: Guru/Budha → 1st, Kuja/Ravi → 10th, Chandra/Shukra → 4th, Shani → 7th

### US-SB-006: Naisargika bala (නෛසර්ගික බලය)

- **Title**: System computes Naisargika bala — present unless the planet is Maranakaraka
- **Story**: As a student, I want Naisargika bala to be checked for every planet except the Maranakaraka, so that the natural strength reflects the maranakaraka rule.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-SB-001; `computeMaranakaraka` (`src/lib/astrology.ts`, rule in `docs/done/maranakaraka.md`)

#### Acceptance Criteria

1. **Maranakaraka planets unchecked**:
    - Given a horoscope where a planet occupies its designated death house (Chandra in the 8th, Rahu in the 9th, Shani in the 1st, Ravi in the 5th, Shukra in the 6th, Kuja in the 7th, Budha in the 4th, Guru in the 3rd), When the table loads, Then that planet's Naisargika checkbox is unchecked with a maranakaraka reason including the triggering house
    - Multiple planets can qualify at once — every qualifying planet is unchecked

2. **All other planets checked**:
    - Given any planet that is not the Maranakaraka, When the table loads, Then its Naisargika checkbox is checked

3. **No maranakaraka present**:
    - Given a horoscope with no matching rule, Then every planet's Naisargika checkbox is checked

4. **Both chart sources**:
    - The rule applies to both auto and manual horoscopes, reusing the existing `computeMaranakaraka` output

#### Business Rules

- Maranakaraka is the planet that occupies its designated house — multiple planets can be Maranakaraka at once; each loses Naisargika bala (never Chandra by default)
- Houses are read from the lagna (rasi) chart only — never the D9 (navamsa) chart
- The tooltip for the unchecked box should reference the triggering house (numeric param) so the student can verify the rule

### US-SB-007: Drishti bala (දෘෂ්ඨි බලය) — manual only

- **Title**: Drishti bala starts unchecked and is set manually by the student
- **Story**: As a student, I want Drishti bala to always start unchecked with an explanatory tooltip, so that I can enter the values the system cannot calculate.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: US-SB-001

#### Acceptance Criteria

1. **Never auto-checked**:
    - Given any horoscope (auto or manual), When the table loads, Then every planet's Drishti checkbox is unchecked

2. **Manual tooltip**:
    - The Drishti checkbox tooltip explains that the value is set manually (the system cannot calculate Drishti bala), e.g. `shadbalaya.drishti.reason.manual`

3. **Student can set it**:
    - The student can check or uncheck the Drishti checkbox for any planet; the value persists (US-SB-008)

#### Business Rules

- No system calculation path sets `drishtiBala.value` to `true`

### US-SB-008: Checkbox toggle with auto-save and persistence

- **Title**: Student toggles any bala and the change auto-saves
- **Story**: As a student, I want to check or uncheck any bala checkbox and have the change saved automatically, so that my corrections persist without a save button.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: US-SB-001

#### Acceptance Criteria

1. **Toggle**:
    - Clicking a checkbox immediately toggles its state (optimistic UI update)
    - The toggle is possible for every bala of every planet — the student is not restricted to "non-calculable" balas

2. **Auto-save**:
    - The change is persisted automatically (immediate or debounced) — there is no separate save action
    - Saving stores the toggle on `CalculatedDetails.shadbalaya` with `overridden: true` for that bala

3. **Persistence**:
    - The saved state survives page refresh, navigation away and logout/login
    - On reload, the checkbox renders the student's value, not the system-computed value

4. **Immediate feedback**:
    - The අනුපාතය column updates immediately after each toggle (US-SB-010)

5. **Failure handling**:
    - If the save fails, the checkbox reverts to its previous state and a localized error message is shown

#### Edge Cases

- **Rapid toggling**: consecutive toggles settle on the latest state (no race between pending saves)
- **Toggle back to the system value**: the bala still records `overridden: true` (the value is preserved even if it coincides with the computed value — see Open Questions)

### US-SB-009: Tooltip reasons for checked and unchecked

- **Title**: Every bala checkbox shows its reason in a tooltip
- **Story**: As a student, I want a tooltip on every bala checkbox explaining why it is checked or unchecked, so that I can understand and verify each value.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: US-SB-001, US-SB-002 through US-SB-007 (per-bala reasons)

#### Acceptance Criteria

1. **Checked reason**:
    - Given a checked bala, When the student hovers the checkbox, Then a tooltip shows the reason(s) it is checked — e.g. Sthana "Uchcha", Cheshta "Vakra", Kala "Because of conjunction with Shukla Chandra", Dig "Planet in 10th house", Naisargika "Not Maranakaraka"

2. **Unchecked reason**:
    - Given an unchecked bala, When the student hovers the checkbox, Then a tooltip shows the reason(s) it is unchecked — e.g. Sthana "Neecha + Shatru", Naisargika "Maranakaraka (in 8th house)"

3. **Multiple reasons**:
    - Given a bala with several applicable conditions, When the student hovers the checkbox, Then every reason is shown (one per line, e.g. a Cheshta planet that is both Vakra and combined with Shukla Chandra)

4. **Manual-state reason**:
    - Given a bala that is manual-only or not yet set, When the student hovers the checkbox, Then the tooltip shows the manual/set-manually reason (e.g. Drishti bala)

5. **Localization**:
    - Tooltip text renders in the active locale (Sinhala or English)

#### Business Rules

- Reasons are composed from i18n keys + numeric enum params stored in `CalculatedDetails.shadbalaya` (e.g. `{ "key": "shadbalaya.sthana.reason.uchcha" }`, `{ "key": "shadbalaya.kala.reason.shuklaChandra", "params": { "planet": 3 } }`) — never stored or rendered from stored localized text

### US-SB-010: Anupatha ratio as (n/6)

- **Title**: Ratio column shows (count of checked balas)/6
- **Story**: As a student, I want the අනුපාතය column to display the ratio as "(n/6)", so that I can see at a glance how many of the six balas a planet holds.
- **Priority**: Medium
- **Actor**: Student
- **Dependencies**: US-SB-001

#### Acceptance Criteria

1. **Format**:
    - Given a planet with 3 checked balas, When the table renders, Then the ratio cell shows `(3/6)`
    - The ratio is displayed as a fraction `(n/6)`, NOT as a divided decimal or percentage

2. **Bounds**:
    - Given 0 checked balas, Then the cell shows `(0/6)`; given 6 checked balas, Then the cell shows `(6/6)`

3. **Live update**:
    - When a checkbox is toggled, the ratio cell updates immediately to the new count (US-SB-008)

4. **All sources**:
    - The ratio renders identically for auto and manual horoscopes

#### Business Rules

- The ratio is derived at render time from the six per-bala `value` flags — it is not stored in `CalculatedDetails.shadbalaya`

### US-SB-011: Sinhala and English i18n

- **Title**: Shad Bala table and tooltips fully localized (SI + EN)
- **Story**: As a Sinhala or English user, I want every Shad Bala label, reason and tooltip in my chosen language, so that the feature is fully usable bilingually.
- **Priority**: Medium
- **Actor**: Student
- **Dependencies**: US-SB-001, US-SB-009

#### Acceptance Criteria

1. **Strings covered**:
    - Column headers (ග්රහයා / Planet, ස්ථාන බල / Sthana Bala, etc.), planet names, reasons and tooltips all exist in both `src/messages/si.json` and `src/messages/en.json`

2. **Message key parity**:
    - `si.json` and `en.json` are kept in sync — no Shad Bala string exists in only one locale

3. **No hardcoded strings**:
    - Component code contains no inline Sinhala/English literals for Shad Bala UI; all text resolves through i18n message keys

4. **Locale switch**:
    - Switching the active language re-renders the table and tooltips immediately (existing `useI18n()` behaviour)

5. **Enum labels reused**:
    - Planet names reuse the existing numeric-Planet → i18n label mapping (no duplicate planet-name strings)

### US-SB-012: Manual horoscope behaviour

- **Title**: Shad Bala on manual horoscopes — only derivable balas auto-computed
- **Story**: As a student working with a manually-entered horoscope, I want the system to auto-calculate only the balas it can derive from the entered chart and leave the rest for me, so that the table reflects the available data.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-SB-001 through US-SB-007

#### Acceptance Criteria

1. **Derivable balas computed**:
    - Given a manual horoscope, When the table loads, Then Sthana, Dig and Naisargika balas are computed from `manualHousePlacements` (entered houses/signs/strengths), and Cheshta/Kala conditions that derive from placements (Moon Shukla paksha, Shukla-Chandra conjunction, Vakra, Moon-paksha Kala conditions) are computed where the input allows

2. **Sign-based Ravi rule**:
    - Given a manual horoscope where Ravi is in Makara, Kumba, Meena, Mesha or Wrushaba, Then Ravi's Cheshta checkbox is checked with the sign-based reason (replaces the Uttarayana condition, which is not computable without birth time/location)

3. **Not computed on manual**:
    - The Uttarayana Cheshta condition, the planet-war Cheshta condition, and the Hora/Panchama/Sukshama varga-load Kala condition are NOT computed on manual horoscopes

4. **Drishti always manual**:
    - Drishti bala is unchecked with the manual tooltip (US-SB-007)

5. **Student fills the gaps**:
    - The student can toggle any non-computed bala (e.g. planet-war Cheshta, Drishti) and the value persists (US-SB-008, US-SB-013)

#### Business Rules

- Manual horoscopes without birth time cannot derive day/night Kala conditions (see Open Questions — PM/domain to confirm whether day/night is derived when a birth time is present or left for the student)

### US-SB-013: Overrides survive the AstrologySettings recalculation

- **Title**: User bala overrides are never wiped by a full recalculation
- **Story**: As a student, I want my manual bala toggles to survive the AstrologySettings full recalculation, so that my corrections are not lost when a Super Admin changes system settings.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-SB-008; `AstrologySettings` recalculation job (`20260812-2111-system-astrology-settings.md`)

#### Acceptance Criteria

1. **Overridden values preserved**:
    - Given a bala with `overridden: true`, When the AstrologySettings recalculation job runs, Then the stored user value is kept unchanged

2. **Non-overridden values recomputed**:
    - Given a bala with `overridden: false`, When the recalculation job runs, Then it is recomputed from the current chart data (and may change)

3. **Parity with manualHousePlacements**:
    - The preservation guarantee matches `manualHousePlacements`, which the recalculation job never overwrites (US-SAS-009)

4. **Verifiable**:
    - Toggling a bala, triggering a full recalculation, and reopening the horoscope shows the user's toggled value intact

#### Business Rules

- The recalculation job treats `shadbalaya` entries with `overridden: true` as read-only; only `overridden: false` entries are recomputed (see `data-model.md` → ShadBalaya notes)

- **Title**: Shad Bala table is read-only for non-owners and share-link viewers
- **Story**: As a student viewing a horoscope I don't own (public horoscope or via a share link), I want the Shad Bala table to be read-only, so that I cannot alter another student's data.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: US-SB-001; existing privacy/share-link rules

#### Acceptance Criteria

1. **Read-only rendering**:
    - Given a horoscope accessed via a share link or owned by another student, When the table renders, Then the bala cells are shown without checkboxes (or with disabled checkboxes) and the tooltips still work

2. **Ratio still shown**:
    - The අනුපාතය column renders as usual on read-only views

3. **Server-side enforcement**:

#### Business Rules

- Only the owner (and Super Admin) may mutate `CalculatedDetails.shadbalaya`; share-link recipients and other students have read access only

## Clarifying Assumptions

1. **A Shatru (enemy sign) placement removes Sthana bala** — whether alone or combined with Neecha (per `docs/shadbalaya.md`: "If some planet in Sathuru rashi the planet has not Sthana bala. (If the planet is in Neecha and Sathuru also it has not the Sthana bala.) Otherwise it has the Sthana bala."). A Neecha placement in a non-enemy sign keeps the bala.
2. **Any one condition suffices** for Cheshta and Kala bala — no requirement to satisfy all conditions; the tooltip lists every satisfied reason.
3. **Numeric-enum conventions** apply throughout: planets are numeric `Planet` (1-9), signs are numeric `ZodiacSign`, houses are 1-12, strength is numeric `PlanetaryStrength`. Reasons are i18n keys + numeric params, never stored localized text.
4. **`overridden: true` is sticky** once a student toggles a bala — even if the toggled value equals the computed value, the bala is treated as a user value and preserved across recalculation.
5. **Uttarayana/planet-war/varga-load conditions are auto-only**; manual horoscopes use the sign-based Ravi fallback and leave planet-war/varga-load/Drishti to the student.
6. **Rahu/Ketu never have Dig bala** (no directional mapping in the rule).
7. **Ratio is render-time derived** `(n/6)` and not stored.

## Open Questions

1. **Hora/Panchama/Sukshama varga-load formula** — `docs/shadbalaya.md` says "calculate the load of Hora, Panchama and Sukshama" but does not define how each load is computed (per-varga planet placement strength? weighted sum? threshold?). Domain/Astrologer to provide the load calculation, or approve a placeholder until confirmed. (PM/Domain)
2. **Day/night on manual horoscopes** — manual horoscopes may lack a birth time. Should Kala day/night conditions be derived when a birth time exists, skipped (left for the student) when it does not, or never computed on manual charts? (PM/Domain)
3. **Uttarayana boundary** — how is Uttarayana determined on auto horoscopes (tropical/-sidereal solstice date vs. Ravi's sign)? `docs/shadbalaya.md` only gives the sign-based fallback for manual. (Domain)
4. **"Combined with Shukla Chandra"** — what defines the conjunction for Cheshta/Kala (same sign, same house, or degree orb — and which orb)? (Domain)
5. **Shukla/Krushna paksha boundary** — paksha derives from thithi (Shukla = tithi 1-15, Krushna = 16-30, Purnima/Amavasya?); confirm the boundary mapping including the exact Purnima/Amavasya treatment. (Domain)
6. **Planet-war data source** — is a planet-war winner already computed anywhere in the calculation engine, or does the engine need a new planet-war module before the 48h Cheshta rule can run? (Developer/Architect)
7. **`overridden` when value matches computed** — should a toggle that coincides with the system value still mark `overridden: true` (assumed), or should the system detect "no effective change" and leave `overridden: false`? (PM/UX)
8. **Manual-state indicator** — should a bala the student set manually be visually distinguished from a system-computed bala (e.g. a dot/strikethrough), or is the tooltip reason sufficient? (UX/PM)
9. **Auto-save granularity** — per-toggle immediate save vs. debounced batch save; behaviour when the save races with a page navigation (e.g. `navigator.sendBeacon` / final flush). (Developer/Architect)
10. **Recalculation scope** — on a full recalculation, are non-overridden balas always recomputed (assumed), and is there any scenario where the recompute would depend on stale varga data not present in the snapshot? (Developer/Architect)
