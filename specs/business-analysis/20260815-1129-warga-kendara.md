## Background / Context

The charts tab of the horoscope detail page currently shows a fixed pair — Birth Chart (D1) and Navamsa Chart (D9) — plus an "Other charts" section (House, Drekkana D3, Dasamsa D10, Shodasha Vargas, Chandra Lagna, Surya Lagna). The calculations tab shows one D1 houses table and one D1 planets table.

This feature — **වර්ග කේනදර (Warga Kendara)** — turns the chart section into a full divisional-chart viewer:

- Each displayed chart carries its **main indication shown as tag chips** directly beneath the chart caption (product decision 2026-08-15 — no separate 16-varga reference table).
- The chart section becomes **tabs** — Rāśi (D1), Navāṁśa (D9), Surya Lagna, Chandra Lagna, etc. **Rāśi (D1) is always selected**; **Navāṁśa (D9) is selected by default**; the student may pick any other available warga chart as the second chart. **Exactly two charts are displayed at once** (like today's D1 + D9).
- The "Other charts" section is reduced to **House only** (the warga charts move into the tabs).
- **Calculation tables** render beneath the two displayed charts, each showing **the data of its own chart** (e.g. for horoscope `6a68e337150a9f9377fab96d`: D1 Saturn | Capricorn | Own Sign | … | Combust, Maranakaraka, Maraka, Kala Bala; D9 Saturn | Cancer | Enemy | …):
  - **Houses table:** `#`, `Sign`, `Planets`, `Aspects`
  - **Planets table:** `Planet`, `Sign`, `Str`, `House`, `Nakshatra (Pada)`, `Bhava Suchika`, `Conjunctions`, `Aspects`, `Other` — **Nakshatra (Pada) and Bhava Suchika columns exist only on the D1 table**; **Conjunctions and Aspects render without degree differences**.
- **D1-only planet details** (never shown on other charts): Wargoththama, Pushkara, Gandantha, Gandamula, 64th Navamsa Lord, 22nd Drekkana Lord, Cheshta Bala, Ashtamansha, Kala Bala, Atmakaraka, Combust, Badhaka.
- **Per-chart planet details** (computed for every chart): Maraka, Maranakaraka, Dig Bala.
- **Phasing:** "Will give guidance for each chart. Now need only Suraya, Chandara, D9, D1 only." — only **Surya Lagna, Chandra Lagna, D9 and D1** are calculable in phase 1; the other vargas are omitted entirely (no tabs, no reference table).

## Warga Kendara Actors

### Student

- **Description**: An astrology student who studies divisional (varga) charts of a horoscope.
- **Warga-Kendara-Specific Goals**: See every warga kendara chart with its purpose, compare any two divisional charts side by side, and study each chart's own houses/planets tables with chart-specific details.
- **Warga-Kendara-Specific Permissions**:
    - View the Warga Kendara varga-chart viewer (tab strip, two displayed charts, main-indication tags, per-chart tables, read-only)
    - View the chart section as warga tabs (Rāśi D1, Navāṁśa D9, Surya Lagna, Chandra Lagna; more vargas in later phases)
    - See D1 always selected; by default D9 is the second selected chart; select any other available warga chart as the second chart (exactly two charts shown at once)
    - View the "Other charts" section showing only the House chart
    - View per-chart Houses and Planets tables beneath each displayed chart (Nakshatra (Pada) + Bhava Suchika columns only on D1; Conjunctions/Aspects without degree differences)
    - View the twelve D1-only planet details only in the D1 tables
    - View Maraka, Maranakaraka and Dig Bala details in every chart's tables
    - View all Warga Kendara content read-only (no editing) on own, public and share-linked horoscopes

### System (Calculation Engine)

- **Description**: Automated services that provide chart data and compute per-chart calculation tables and details.
- **Warga-Kendara-Specific Responsibilities**:
    - Maintain the static Warga Kendara catalog (16 vargas: D#, chart name, main indication) that supplies each displayed chart's main-indication tags — bilingual display data resolved via i18n
    - Provide chart data per warga tab: phase 1 = Rāśi (D1), Navāṁśa (D9), Surya Lagna, Chandra Lagna; later phases add the remaining vargas per guidance
    - Compute per-chart calculation tables (Houses: #/Sign/Planets/Aspects; Planets: Planet/Sign/Str/House/Conjunctions/Aspects/Other) using each chart's own signs, strengths and houses
    - Compute per-chart planet details: the twelve D1-only details for D1; Maraka/Maranakaraka/Dig Bala for every chart
    - Persist per-chart data on `CalculatedDetails.wargaKendara`, recompute on the AstrologySettings full recalculation job, and provide a render-time fallback for legacy documents

### US-WK-001: Main indication shown as tags after each chart

- **Title**: Student sees each displayed chart's main indication as tags
- **Story**: As a student, I want each displayed warga chart to show its main indication as tag chips right after the chart caption, so that I immediately know what that varga represents before studying its tables.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: Static Varga Chart Catalog (see `data-model.md` → [Varga Chart Catalog](#))

#### Acceptance Criteria

1. **Tags after each chart**:
    - Each displayed chart figure renders its main indication as one or more tag chips directly beneath the chart caption (above the Houses table)
    - The tags split the indication string on `,`/`;` into chips (e.g. D1 indication "සමස්ත ජීවිතය, ශරීරය, පොදු තත්ත්ව" → three chips; EN "Overall life, body, general circumstances" → four chips)

2. **Catalog-sourced**:
    - Tag text matches `docs/warga-kendara.md` exactly and comes from the static catalog (i18n `astrology.wargaKendara.vargas.*.indication`) — never stored per horoscope, never user-editable
    - Phase 1 renders tags for the displayable charts only: D1 Rāśi, D9 Navāṁśa, Surya Lagna, Chandra Lagna

3. **Bilingual**:
    - Tags render in Sinhala or English according to the active locale (existing `useI18n()` re-render behaviour)

#### Edge Cases

- **Locale switch**: switching the active language re-renders the tags immediately (existing `useI18n()` behaviour)
- **Long indication text**: tags wrap to multiple lines on narrow viewports — no horizontal scroll (UX decision)
- **Missing catalog entry**: if no indication resolves for a chart, the tag row renders as `—` (never empty/crash)

#### Business Rules

- The catalog is static, system-wide reference data — never stored per horoscope, never user-editable
- English names/indications are authoritative from the feature document; Sinhala translations are pending domain confirmation (see Open Questions)

- **Title**: Student switches warga charts via tabs instead of the fixed Birth & Navamsa pair
- **Story**: As a student, I want the chart section to show the warga charts as tabs — Rāśi (D1), Navāṁśa (D9), Surya Lagna, Chandra Lagna (and other vargas in later phases) — instead of the fixed "Birth & Navamsa" pair, so that I can switch which divisional charts I study.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: US-WK-009 (phase-1 availability); existing chart data (`birth`, `navamsa-d9`, `surya-lagna`, `chandra-lagna` chart types)

1. **Tab strip replaces the pair**:
    - The "Birth & Navamsa" fixed pair is removed; a tab strip offers Rāśi (D1), Navāṁśa (D9), Surya Lagna, Chandra Lagna (phase 1)
    - Tab labels are bilingual, e.g. "රාශි (D1)" / "Rāśi (D1)", "නවාංශ (D9)" / "Navāṁśa (D9)"

3. **Accessibility**:
    - The tab strip is keyboard-operable with proper `aria` (selected state, tablist semantics)

#### Edge Cases

#### Business Rules

### US-WK-003: Chart selection — D1 always selected, exactly two charts

- **Title**: D1 is always selected, D9 by default; the student picks the second chart
- **Story**: As a student, I want Rāśi (D1) to be always selected with Navāṁśa (D9) selected by default, and to choose any other available warga chart as the second chart, so that exactly two charts appear side by side as they do today.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: US-WK-002 (tabs)

#### Acceptance Criteria

1. **Default view**:
    - Given a freshly opened horoscope, When the charts tab renders, Then Rāśi (D1) and Navāṁśa (D9) are displayed side by side (the default = D1 + D9)

2. **D1 is fixed**:
    - D1 cannot be deselected — it is always one of the two displayed charts
    - Given the D1 tab is selected, When the student clicks the D1 tab again, Then nothing changes (it stays selected; no chart is removed)

3. **Second-chart selection**:
    - Given D1 + D9 displayed, When the student selects Surya Lagna, Then the view shows D1 + Surya Lagna (D9 is replaced)
    - Exactly two charts are displayed at any time — selecting a tab always swaps the second chart, never adding a third

4. **Re-select the current second chart**:
    - Given D1 + D9 displayed, When the student clicks the Navāṁśa (D9) tab again, Then the view is unchanged (no-op)

#### Edge Cases

- **Rapid switching**: quickly selecting several tabs settles on the last selection with exactly two charts
- **Chart without data** (e.g. manual horoscope without Navamsa data): the D9 tab is still selectable but renders the existing "no chart data" placeholder (see US-WK-010)
- **Horoscope change**: navigating to another horoscope resets the second chart to the default (D9)

#### Business Rules

- Selection state is client-side only in phase 1 (no persistence requirement — see Open Questions)
- D1 is a fixed member of the pair; the second chart defaults to D9

### US-WK-005: Per-chart Houses table

- **Title**: Student views a Houses table (#, Sign, Planets, Aspects) under each displayed chart
- **Story**: As a student, I want a Houses table with columns `#`, `Sign`, `Planets`, `Aspects` beneath each displayed chart showing that chart's house data, so that I can study the houses of each divisional chart.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: US-WK-003 (two displayed charts); per-chart house data (auto: D1 `houses` / D9 navamsa houses / Surya-Chandra rotation; manual: entered placements)

#### Acceptance Criteria

1. **Table placement and columns**:
    - Beneath each of the two displayed chart figures, a Houses table renders with exactly the columns `#`, `Sign`, `Planets`, `Aspects`

2. **Data of its own chart**:
    - The table shows that chart's data: 12 rows (houses 1-12), `Sign` per that chart's lagna (whole-sign), `Planets` placed in that chart's houses, `Aspects` into that house computed within that chart
    - Example (`6a68e337150a9f9377fab96d`): the D1 houses table uses the D1 houses; the D9 houses table uses the D9 (navamsa) houses

3. **Both chart sources**:
    - The table renders for `source: "auto"` and `source: "manual"` horoscopes (manual limited to derivable charts — see US-WK-010)

#### Edge Cases

- **Empty house**: no planets → the cell shows "—"
- **Chart without calculable data**: the table area shows the existing "no chart data" placeholder instead of an empty table (see US-WK-010)

#### Business Rules

- House rows use numeric `ZodiacSign` enums and whole-sign house assignment per chart lagna (mirroring the existing D9 derivation in `getNavamsaChartData`)
- Aspects display without degree differences (per feature doc)
- No user editing — display only

### US-WK-006: Per-chart Planets table

- **Title**: Student views a Planets table per chart — Nakshatra (Pada) and Bhava Suchika only on D1, no degree differences
- **Story**: As a student, I want a Planets table (`Planet`, `Sign`, `Str`, `House`, `Conjunctions`, `Aspects`, `Other`) under each displayed chart — with `Nakshatra (Pada)` and `Bhava Suchika` columns only on the D1 table and no degree differences in Conjunctions/Aspects — so that I can study each chart's planetary picture.
- **Priority**: High
- **Actor**: Student
- **Dependencies**: US-WK-003 (two displayed charts); per-chart planet data; US-BS-001/US-BS-002 (Bhava Suchika for the D1 column)

#### Acceptance Criteria

1. **Columns**:
    - Each chart's planets table renders the columns `Planet`, `Sign`, `Str` (Strength), `House`, `Conjunctions`, `Aspects`, `Other`
    - The `Nakshatra (Pada)` and `Bhava Suchika` columns render **only in the D1 table** and are omitted for D9, Surya Lagna and Chandra Lagna tables

2. **Per-chart values**:
    - `Sign`/`Str`/`House` reflect that chart: e.g. for `6a68e337150a9f9377fab96d`, the D1 Saturn row shows Capricorn | Own Sign and the D9 Saturn row shows Cancer | Enemy
    - All 9 planets (including Rahu and Ketu) appear as rows in every chart's table

3. **Conjunctions without degree difference**:
    - The `Conjunctions` cell lists conjunct planets by name only (e.g. "සිකුරු" / "Venus") — no `(±dd:mm:ss)` degree difference
    - A planet with no conjunctions shows "—"

4. **Aspects without degree difference**:
    - The `Aspects` cell lists aspected planets by name/aspect only — no degree-gap detail
    - A planet with no aspects shows "—"

5. **Other column per chart**:
    - The `Other` cell shows the chart-appropriate details per US-WK-007 (D1-only set) and US-WK-008 (Maraka/Maranakaraka/Dig Bala for every chart)

#### Edge Cases

- **Bhava Suchika absent** (legacy/manual without Navamsa): the D1 Bhava Suchika cell shows "—" (existing fallback behaviour)
- **Chart without calculable data**: the table area shows the "no chart data" placeholder

#### Business Rules

- All values are numeric enums (Planet 1-9, ZodiacSign, PlanetaryStrength, house 1-12); display names resolve via i18n
- No degree strings render in Conjunctions/Aspects cells for any per-chart table
- Conjunction/aspect computation per chart reuses the existing aspect logic against the chart's own planet positions (exact rule — see Open Questions)

### US-WK-007: D1-only planet details

- **Title**: The twelve D1-only details appear only in the D1 tables
- **Story**: As a student, I want the twelve D1-only planet details — Wargoththama, Pushkara, Gandantha, Gandamula, 64th Navamsa Lord, 22nd Drekkana Lord, Cheshta Bala, Ashtamansha, Kala Bala, Atmakaraka, Combust, Badhaka — to appear only in the D1 planets table, so that chart-specific indicators are not shown on other charts.
- **Priority**: High
- **Actor**: Student, System
- **Dependencies**: US-WK-006 (Other column); existing `CalculatedDetails` fields (`wargoththamaPlanets`, `gandanthaPlanets`, `gandamulaPlanets`, `pushkaraPlanets`, `lord22ndDrekkana`, `lord64thNavamsa`, `cheshtaBala`/`kalaBala` from `shadbalaya`, `ashtamanshaPlanets`, `atmakaraka`, `p.combustion`, `badhakaPlanet`)

#### Acceptance Criteria

1. **D1 Other cell**:
    - Given a D1 planets table, When a planet qualifies, Then its `Other` cell shows any combination of the twelve D1-only details
    - Example (`6a68e337150a9f9377fab96d`): the D1 Saturn row shows Combust and Kala Bala among its details

2. **Other charts never show them**:
    - Given a D9, Surya Lagna or Chandra Lagna planets table, When a planet would qualify for a D1-only detail in D1, Then the detail is NOT shown (these tables show only Maraka/Maranakaraka/Dig Bala per US-WK-008)

3. **No details → "—"**:
    - Given a planet with none of the applicable details, When the Other cell renders, Then it shows "—"

#### Edge Cases

- **Wargoththama crossed out**: a Wargoththama planet that is also Gandantha/Gandamula keeps the existing strikethrough treatment in the D1 table
- **Details present in legacy docs**: existing D1 fields feed the D1 table as today (no recomputation needed for D1)

#### Business Rules

- The twelve details are D1-exclusive by definition — they are derived from birth-chart (D1) considerations only and never appear on other charts
- Existing computed fields/arrays are reused for D1; no new D1 calculations are introduced by this story

### US-WK-008: Per-chart Maraka, Maranakaraka and Dig Bala

- **Title**: Maraka, Maranakaraka and Dig Bala are computed for every chart's tables
- **Story**: As a student, I want Maraka, Maranakaraka and Dig Bala to be calculated for every chart's planets table (D1, D9, Surya Lagna, Chandra Lagna), so that these chart-sensitive details are visible per divisional chart.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-WK-006 (Other column); per-chart house data; domain confirmation of the per-chart rules (see Open Questions)

#### Acceptance Criteria

1. **Every chart shows them**:
    - Each chart entry's `Other` cell can show Maraka, Maranakaraka and/or Dig Bala, computed relative to that chart's own lagna and houses

2. **Per-chart computation**:
    - Dig Bala reuses the existing house-based mapping (Guru/Budha 1st, Kuja/Ravi 10th, Chandra/Shukra 4th, Shani 7th) evaluated against the chart's own houses; Rahu/Ketu never show Dig Bala (no mapping exists)
    - Maraka and Maranakaraka are computed per chart using the per-chart rule once confirmed (see Open Questions — the current Maranakaraka rule is documented "lagna chart only, never D9")

3. **Example**:
    - For `6a68e337150a9f9377fab96d`, the D1 Saturn row shows Maranakaraka and Maraka (as in the feature doc example)

#### Edge Cases

- **Planet with no per-chart details**: the `Other` cell shows "—"
- **Rahu/Ketu**: never receive Dig Bala in any chart

#### Business Rules

- Per-chart values are pure derived data — computed at calculation time, persisted in `CalculatedDetails.wargaKendara[chart]`, recomputed on the AstrologySettings recalculation job, no user overrides
- The per-chart rules for Maraka and Maranakaraka must be confirmed by the domain before implementation (see Open Questions)

### US-WK-010: Manual horoscopes

- **Title**: Warga Kendara works on manually-entered horoscopes from entered/derived data
- **Story**: As a student with a manually-entered horoscope, I want the warga tabs and per-chart tables to work from my entered data (and the D9 / Surya Lagna / Chandra Lagna charts derived from it), so that the feature behaves consistently across both sources.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-WK-005, US-WK-006; `manualHousePlacements` (`navamsaLagna` / `navamsaHouses`, `planetDegrees`)

#### Acceptance Criteria

1. **D1 tables**:
    - Given a manual horoscope, When the D1 chart and its tables render, Then they use the entered placements (`manualHousePlacements`)

2. **D9 tables**:
    - Given a manual horoscope with entered Navamsa data, When the D9 chart and its tables render, Then they use the entered Navamsa chart (navamsa lagna / navamsa houses)
    - Given a manual horoscope without entered Navamsa data, When the D9 tab is selected, Then it renders the existing "no chart data" placeholder (no empty tables)

3. **Surya/Chandra Lagna tables**:
    - Given a manual horoscope, When the Surya Lagna or Chandra Lagna tab is selected, Then the chart and tables derive by rotating the entered chart to the Sun's / Moon's sign (existing `getSunMoonChartData` behaviour)

#### Edge Cases

- **Partial Navamsa input** (lagna only, houses only, or neither): the D9 table renders whatever is derivable or the placeholder — mirroring the existing partial-input behaviour of the navamsa enrichment (see Open Questions)
- **D1-only details on manual charts**: D1-only flags that the system cannot derive on manual charts simply do not appear (consistent with existing manual-chart limitations, e.g. Kala varga loads)

#### Business Rules

- `manualHousePlacements` remains the single source of truth for the manual chart — derived warga tables never overwrite it
- The same per-chart structure applies to both sources (uniform `wargaKendara[chart]` entries)

### US-WK-011: Storage, recalculation and legacy documents

- **Title**: Warga Kendara data persists, survives recalculation and has a render-time fallback
- **Story**: As a student, I want the per-chart Warga Kendara data to be stored with the horoscope and to remain correct after a full recalculation, so that the tables work consistently across sessions and system changes.
- **Priority**: High
- **Actor**: System
- **Dependencies**: US-WK-005, US-WK-006, US-WK-008; `AstrologySettings` recalculation job (`20260812-2111-system-astrology-settings.md`)

#### Acceptance Criteria

1. **Persisted on CalculatedDetails**:
    - Given a computed horoscope (auto or manual), When it is saved, Then `CalculatedDetails.wargaKendara` stores the per-chart entries (`d1`, `d9`, `suryaLagna`, `chandraLagna` for phase 1) per the [WargaKendara](#) structure

2. **Recomputed on full recalculation**:
    - Given the AstrologySettings full recalculation job runs, When it processes a horoscope, Then `wargaKendara` is recomputed from the current chart data — there are no `overridden` flags to preserve (unlike Shad Bala)

3. **Legacy render-time fallback**:
    - Given a horoscope stored before the field existed, When the charts tab renders, Then the per-chart tables are derived at render time from the always-stored D1 data plus the derived D9 / Surya Lagna / Chandra Lagna charts, so legacy documents still render correct tables

4. **Read-only on all views**:
    - The tables are display-only on own horoscopes, public horoscopes and share links — no mutation endpoint is introduced

#### Business Rules

- `wargaKendara` is pure derived data: persisted for performance/consistency, recomputed on recalculation, derivable at render time as a fallback — no user-editable state exists

- **Title**: Warga Kendara content is read-only on own, public and share-linked horoscopes
- **Story**: As a student, I want the Warga Kendara tab strip, indication tags and per-chart tables to be viewable read-only everywhere a horoscope is viewable, so that no unintended editing exists.

## Clarifying Assumptions

1. **Table placement**: the per-chart calculation tables render in the **charts tab**, directly beneath each displayed chart figure (each figure is followed by its own Houses + Planets tables). The existing **calculations tab** keeps its current D1 tables unchanged (Start/Mid/End, Navamsa columns, degree differences remain there). (UX to confirm the exact layout.)
2. **Exactly two charts, D1 fixed**: Rāśi (D1) is always one of the two displayed charts and cannot be deselected; the second chart defaults to Navāṁśa (D9) and can be swapped for any other available warga chart. Selecting a tab swaps the second chart — never a third chart.
3. **Phase 1 = Surya Lagna, Chandra Lagna, D9, D1 only** ("Now need only Suraya, Chandara, D9, D1 only"). The other 12 vargas are omitted entirely in phase 1 — no tabs, no reference table (product decision 2026-08-15).
4. **D1 Other column content**: per the feature-doc example (`Saturn | Capricorn | Own Sign | … | Combust, Maranakaraka, Maraka, Kala Bala`), the D1 table shows the D1-only set **plus** Maraka/Maranakaraka/Dig Bala; other charts show only Maraka/Maranakaraka/Dig Bala. Whether Yogakaraka/Nidhanamsha (currently in the calculations-tab Other column but absent from the feature doc's D1-only list) also appear on the D1 per-chart table is an Open Question.
5. **Per-chart values**: `Sign`/`Str`/`House` for D9 use the planet's navamsa sign/strength/house (already stored/derived); for Surya/Chandra Lagna they use the rotated chart's values. Conjunctions/aspects are computed within the chart itself (same rules, chart's own positions) and rendered **without** degree differences.
6. **Storage convention**: per-chart data persists on `CalculatedDetails.wargaKendara` following the `shadbalaya`/`bhavaSuchika` precedent (computed at calculation time, recomputed on AstrologySettings recalculation, render-time fallback for legacy documents, no user overrides).
7. **Varga catalog**: the 16 varga names and indications are static system-wide display data resolved via i18n; English is authoritative from the feature doc; Sinhala translations are pending.
8. **Numeric-enum conventions** apply throughout: planets 1-9, signs 1-12, houses 1-12, `PlanetaryStrength` values — never display strings in storage.
