## Overview

The Student Notepad is a **draggable, resizable, always-available study surface** on the horoscope detail page. Every viewing student gets their **own private notepad per horoscope** — it shows the seven system observation groups (planets in house, house load, nakshatra load, significator planets, Chandra/Surya Lagna related houses, related Warga Kendara) derived from the horoscope's `CalculatedDetails`, plus the student's own color-coded **observation tags** (grouped by house topic / sub-topic) and **result notes**. Everything the student writes persists to the DB per horoscope with debounced auto-save, and reopening the notepad restores its geometry, open/closed state, and last-selected topic.

This is the **most important feature of the platform** ("most important implementation of this project") — it is the student's personal study workspace, so the design centers on: (a) zero-friction capture, (b) instant per-horoscope context switching, (c) trustworthy persistence (nothing lost on close, navigate, or refresh).

### UX goals

1. **One click to the workspace** — the notepad opens from the detail-page header on every horoscope view (owner and public viewers alike; every viewer gets their own private copy).
2. **Scan before you click** — the seven system observation groups stack in a fixed order with `(n/m)` green ratios, so a student can scan a topic's strength in seconds.
3. **Capture in context** — the student-tag composer is always pre-contexted to the currently selected house topic / sub-topic; selecting a topic is the same gesture that frames where a new tag lands.
4. **Nothing lost** — optimistic UI + debounced auto-save + keepalive flush on close/navigate/refresh + full restore on reopen.
5. **Bilingual parity** — every string exists in both Sinhala and English; catalog strings use the existing EN-fallback convention while SI translations are pending.

---

## Locked-in requirements (from Architecture spec)

These are non-negotiable and shape every interaction below:

- **Observations change with the horoscope** — navigating between horoscopes instantly swaps observation sections, student tags, result notes, and popup geometry. State is per-(student, horoscope); there is no cross-horoscope leakage and no stale flash.
- **All student modifications persist per horoscope** — debounced auto-save with optimistic UI, rollback + localized toast on failure, keepalive flush on close/navigate, and restore-on-reopen.

## Answers to the Architect's Handoff checklist

### Q1 — Popup shell (geometry, drag, resize, z-index, entry point)

**Decision: right-docked default, drag via header, resize via corner handle, `z-40`, header-action entry button.**

- **Entry button** — first position in the detail-page header action row (`page.tsx:1019`, `flex items-center gap-2 shrink-0`), **before** the owner-only Edit/Privacy buttons. It is available to **all** viewers (owner + public). Styling: 40px-tall outline button, icon (notebook) + short label `සටහන් පොත` / `Notepad` (label collapses to icon-only below 640px), `title`/`aria-label` = full name `ශිෂ්ය සටහන් පොත` / `Student Notepad`. When the popup is open the button renders the active treatment (`bg-indigo-100 text-indigo-600 border-indigo-200`, matching the Edit-button active state at `page.tsx:1029`). A small **content dot** (indigo, top-right of the button, `aria-hidden`, `title` = "You have saved notes here") shows when the horoscope's notepad has any saved tags/notes — signals content exists even while the popup is closed.
- **Default geometry (first open, no saved state)**: size `480×640` (within bounds), **right-docked** — `x = viewportWidth − width − 16`, `y = 80`. Right-docking keeps the D1 chart (left) visible while the student works.
- **Bounds**: min `320×400`, max `900×1200` (architect constants). Position and size are **clamped to the viewport** on every open/restore/resize — the popup can never sit fully off-screen; on small screens the viewport clamp takes precedence over the min bound (a 300px-wide viewport wins over the 320px min).
- **Drag**: the popup **header** is the drag handle (pointer events — mouse/touch/pen unified; `touch-action: none` on the handle; min 44px tall; `cursor: grab` / `grabbing`). Position updates 1:1 with the pointer during drag (no transition). Geometry is committed to the debounced save on **pointer-up only** (not mid-drag).
- **Resize**: a single **bottom-right corner handle** (16×16px touch zone) with `touch-action: none`; diagonal resize keeps the top-left anchored. `width = clamp(value, 320, min(900, vw − 32))`, `height = clamp(value, 400, min(1200, vh − 32))`. Committed on pointer-up.
- **Z-index**: `z-40` — above all page content, **below** modals (`ConfirmDeleteModal`/`QuickAddLocationModal` at `z-50`), toasts (`z-50`) and tooltips (`z-50`, ShadBalaTooltip/AspectTooltip convention). The save-failure toast therefore renders above the popup.
- **Close affordances**: header `✕` button, `Escape` (restores focus to the page entry button), and the page button toggle. **No outside-click dismissal** — it is a non-modal study surface and accidental dismissals would lose context. The popup is `role="dialog"` with `aria-modal="false"` (non-modal; page remains reachable behind it).
- **Keyboard geometry control** (full alternative to drag/resize): with focus inside the popup — `Ctrl+Alt+Arrow` nudges position 8px per step; `Ctrl+Alt+Shift+Arrow` resizes 16px per step; a small "Reset position" button in the popup header restores the right-docked default. (Plain `Alt+Arrow` is avoided: `Alt+Left/Right` is browser back/forward.)
- **Open/close animation**: 150ms fade + 8px vertical translate; the page button and header `✕` share the same affordance weight. No animation during drag/resize.
- **Auto-open**: the popup **auto-opens on load** when the saved `notepadState.isOpen === true` (restore of the full working context — see Q5). Otherwise it stays closed behind the button/badge.

### Q2 — Parent tag strip (13 topics, single-select)

**Decision: 13 wrap chips, `aria-pressed` radio semantics, roving tabindex, "Other" hides sub-tags and observations.**

- **Chip set**: 12 houses + Other (`0`). Chip label format follows the feature doc: `<number> — <purpose>`, e.g. `1 — The person`, `0 — Other`. The number is a fixed-width prefix so all chips align; EN labels from `docs/student-notes.md` (see i18n inventory), **SI labels pending → EN fallback** (catalog convention).
- **Layout**: `flex flex-wrap gap-1.5` — chips **wrap** (no horizontal scroll: wrap keeps all 13 topics visible and avoids a hidden-scroll affordance; at 480px width this yields 2–3 rows in Sinhala, which is acceptable). Chips are single-line (`whitespace-nowrap`); the strip wraps whole chips.
- **Semantics**: a labeled `role="group"` of toggle buttons with `aria-pressed` (single selection, so radio/tablist semantics do not strictly apply; `aria-pressed` matches the existing chips convention). Roving tabindex (one chip tabbable), arrow keys move focus, `Space`/`Enter` selects, `Home`/`End` jump. Group label: `notepad.aria.parentStrip` ("Select a house topic" / SI pending).
- **Selection behavior**: single-select — clicking the already-selected chip is a **no-op**. Selecting a different parent: (a) sets `selectedParentTag`, (b) **resets `selectedSubTag` to null** (architect), (c) re-derives the observation sections, (d) re-groups student tags. Selected chip: `bg-indigo-600 text-white` (existing active-pill treatment). Default on first open: **no parent selected** → the observation area shows a localized hint ("Select a house topic to see its observations") and the student-tag area shows the overview grouping (Q4/Q2 below).
- **"Other" (`0`)**: renders **no sub-tag row and no observation sections** — the student-tag area takes the full content column (tags whose `parentTag === 0` never carry a `subTag`; US-SN-010 AC2).
- **Sub-tag chips**: a second labeled `role="group"` of `aria-pressed` chips (smaller, `text-xs`), same roving-tabindex behavior, listing the selected parent's signification sub-tags (e.g. house 1 → Self, Body, Personality, Identity, Vitality, Appearance). Selecting a sub-tag sets `selectedSubTag` and re-derives sections; a second click on the selected sub-tag is a **no-op** (only the parent click resets). Sub-tag labels EN from the feature doc, **SI pending → EN fallback**.

### Q3 — Colors (TagColor palette vs system classification)

**Decision: keep the six-color palette for student tags (green/red/white/blue/yellow/purple = enum 1–6); give student chips a distinct visual language so they can never be confused with system green/red/white tags; default color = white (neutral).**

- **Student tag chips (TagColor)**: rounded-**square** (`rounded`), **dashed 2px border**, tinted background, color-coded per palette value; hover reveals a pencil (edit) affordance, delete `×` sits on the chip. The dashed square shape + the fact that student tags only ever appear inside the "My observations" section + the edit/delete affordances separate them from system tags even when a student picks green/red/white.
  - 1 Green: `border-green-400 bg-green-50 text-green-800`
  - 2 Red: `border-red-400 bg-red-50 text-red-800`
  - 3 White: `border-gray-300 bg-gray-100 text-gray-700`
  - 4 Blue: `border-blue-400 bg-blue-50 text-blue-800`
  - 5 Yellow: `border-amber-400 bg-amber-50 text-amber-900`
  - 6 Purple: `border-purple-400 bg-purple-50 text-purple-800`
- **Color picker (composer)**: a 6-swatch `role="radiogroup"` (single-select within the composer); each swatch is a 20×20px round button with `aria-label` = color name (`notepad.tagColors.1..6`); the selected swatch shows a ✓ glyph + ring. **Default = white (TagColor 3, neutral)** — an unconsidered default must not assert good/bad. Swatch order follows the enum: Green, Red, White, Blue, Yellow, Purple. The palette itself is provisional pending BA open question 7 (confirm with PM/Domain; the enum values 1–6 are fixed regardless of name/localization).
- **System observation tags (green/red/white)**: rounded-**full** pills with a leading **status dot** (`●`, `aria-hidden`) + tinted border/background — the dot glyph is the non-color channel. Green `border-green-300 bg-green-50 text-green-800` + `text-green-600` dot; Red `border-red-300 bg-red-50 text-red-800` + `text-red-600` dot; White `border-gray-300 bg-white text-gray-700` + `text-gray-400` dot. Each system chip's `aria-label` includes the classification word ("good"/"bad"/"neutral" via `notepad.observation.classification.*`). System color is a **render-time classification only — never stored** (data-model rule; student tags are the only stored colors).
- The system classification (green = good/strong, red = bad/afflicted, white = neutral) is defined by the domain rules **pending** (BA open questions 1–2); the UI renders whatever classification the derivation module emits.

### Q4 — Section stacking + ratio

**Decision: fixed-order scroll (no accordion), ratio badge `(n/m)` right-aligned in each section header, single empty-state rule.**

- **Container**: the popup body is one scrollable column (`overflow-y-auto`, ~48px bottom padding so the corner handle never covers content). **No accordions** — scanning all seven groups is the core interaction; collapsing would hide the signal behind clicks.
- **Fixed section order** (feature-doc order):
  1. `planetsInHouse` — ග්රහයෝ / Planets in this house
  2. `houseLoad` — භාව භාරය සහ ස්ථානය / House load & position
  3. `nakshatraLoad` — නැකත් භාරය සහ ස්ථානය / Nakshatra load & position
  4. `subTagPlanet` — කාරක ග්රහයෝ / Significator planets
  5. `chandraLagnaHouse` — චන්ද්ර ලග්නයේ අදාළ භාවය / Chandra Lagna — related house
  6. `suryaLagnaHouse` — සූර්ය ලග්නයේ අදාළ භාවය / Surya Lagna — related house
  7. `wargaKendara` — අදාළ වර්ග කේනදර / Related Warga Kendara
- **Section header**: small-caps indigo label (existing section-header treatment) + **ratio badge** `(n/m)` right-aligned (`text-xs text-gray-500`, pill), where `n` = green count and `m` = total tags in that section.
- **Ratio rule (single testable rule)**: the badge renders **whenever the section renders at least one tag** — an all-white section shows `(0/m)`; a not-available section shows `(0/1)`. A section with **zero tags** renders its **localized empty-state text and no ratio badge** (e.g. "No planets in this house" / "මෙම භාවයේ ග්රහයන් නැත") — `(0/0)` is noise; the sentence is the information. Not-available (derivation failed / `calculatedDetails` null) renders a single white neutral chip with label "Not available" / "ලබා ගත නොහැක".
- **Planet chips** (sections 1 & 4): inline = `glyph + name · sign · house` (reusing the chart-renderer planet glyphs), e.g. `● ☉ රවි · සිංහ · 5`. Hover/focus shows the existing tooltip pattern (ShadBalaTooltip/AspectTooltip: `fixed`, `z-50`, pointer-events-none, white card) with strength + nakshatra (pada) + house. **Conjunctions/aspects in the tooltip are deferred** — the render contract `ObservationTagBase` has no aspects/conjunctions fields (see Questions → Architect/Developer).
- **House-load chip** (section 2, provisional neutral): label composition e.g. `භාව භාරය: 7 · ග්රහ 2 · තුලා` / `House load: 7 · Planets 2 · Libra` — `labelKey + params` per the architect's contract; colors stay neutral until the domain definitions land.
- **Nakshatra-load chip** (section 3): `නැකත් භාරය: චිත්රා 1` / `Nakshatra load: Chitra 1`.
- **Chandra/Surya house chips** (sections 5 & 6): `chart · house · planets · loadCount` e.g. `චන්ද්ර ලග්නය · 7 වන භාවය · ග්රහ 2 · භාරය 1`; entry-null → not-available chip.
- **Warga section** (section 7, provisional D9): three chips — warga lagna (`D9 ලග්නය · කන්යා · භාරය 1`), related house, and D1 load in warga (`D1 භාරය: කුජ · මකර · 11 · නීච`); mapping fixed to D9 in phase 1 (per-subject warga mapping out of scope).
- **Student-tag grouping** (NotepadStudentTags, per US-SN-011 AC4): no parent selected → **overview grouping** (all parents with ≥1 tag, small parent headers, newest first within group — prevents a dead end on first open); parent selected → that parent's tags (all sub-tags combined + `parentTag`-only tags); parent + sub-tag selected → that exact context's tags.
- **Result notes** (NotepadResultNotes): newest-first list below the tags; visually distinct (cards, not chips).

### Q5 — Restore-on-reopen (BA open question 10 — decided)

**Decision: persist `isOpen` + `selectedParentTag` + `selectedSubTag` + geometry in `notepadState`; auto-open when `isOpen === true`; restore selection and geometry (clamped); stale `subTag` falls back to parent-only.**

- Rationale: US-SN-013 AC5 promises "restores everything from the DB" — the student left the workspace open on purpose; reopening it (position, size, topic, notes) is the whole point of persistence. The popup is non-modal and one click to dismiss, so auto-open is low-cost.
- **Horoscope switch**: navigation applies the **target horoscope's own state** — including closing the popup if its `isOpen` is false (correct per-horoscope restore; no leakage from horoscope A).
- **Stale selection**: if the restored `selectedSubTag` no longer exists in the catalog, restore `selectedSubTag = null` (parent-only) and continue — never crash, never block.
- Selection changes go through the same debounced save pipeline as content edits (they are part of the same PUT document).

### Q6 — Caps

**Decision: confirm BA proposal — 500 chars per observation tag, 2000 chars per result note; count caps 200 tags / 100 notes per horoscope.**

- Enforcement: `maxLength` on the inputs (physical ceiling — no truncation ever) + a **live counter** `n/500` / `n/2000` under the field (`text-xs text-gray-400`; amber ≥80%, red at 100%). Counter is `aria-describedby`-linked to the field.
- Count caps: at 200 tags or 100 notes the composer/input is **disabled** with a localized message (`notepad.studentTags.limitReached` / `notepad.resultNotes.limitReached`).
- Text wraps inside chips/cards (`break-words`); no horizontal scroll anywhere in the popup.

### Q7 — i18n

**Decision: a new top-level `notepad.*` message block in both `en.json` and `si.json`** (sibling of `horoscope.*`/`astrology.*`; the architect's `useMessages` pattern resolves it). Full key inventory in the i18n section below. **Catalog strings (house purposes, sub-tags, Sanskrit names, significations, section headers) are SI-pending → EN fallback** per the existing convention; only the core chrome strings ship with provisional SI now.

### Q8 — Explicitly out of scope (phase 1)

- Notepad on share links (share page is a stub) and on search result cards.
- Mobile full-screen takeover — the popup stays a popup on mobile (clamped to the viewport, touch drag/resize); no separate mobile layout.
- Per-subject warga mapping (related warga fixed to D9).
- Conjunctions/aspects detail inside planet-tag tooltips (data not in the render contract — flagged to Architect/Developer).
- Dark-mode-specific palette tuning — student TagColor classes follow the existing design tokens in both modes.
- Cross-student visibility, super-admin review of student notes (privacy: notepad is never visible to other students, on public views, or share links — architecture QA column).

## User Flows

### Flow 1 — Open and scan a topic (default)

```
Detail page → click [සටහන් පොත] button
  → popup opens right-docked (480×640, auto-open if saved isOpen=true)
  → no parent selected: hint panel + overview student-tag grouping
  → click "5 — What he/she creates and knows"
      → sub-tag row appears (Intelligence, Children, Creativity, …)
      → observation sections re-derive (planets in 5th, house load, …)
      → student tags re-group to house 5
  → scan section ratios (3/4) etc.
```

### Flow 2 — Capture a student tag

```
Select topic (parent + sub-tag) → "My observations" section
  → composer: text input (maxLength 500, counter) + 6 color swatches (default White)
  → type "Mercury strong in 5th" → pick Green → [Add]
      → chip appears instantly (optimistic), scheduled save
      → input clears, focus returns to input (rapid capture)
  → 500ms later PUT succeeds silently (no toast — the state IS the feedback)
  → if PUT fails: chip reverts + toast "Save failed" (3s auto-clear)
```

### Flow 3 — Persistence across close/navigate/refresh

```
Drag popup → position commits on pointer-up → debounced save
Resize → size commits on pointer-up → debounced save
Escape / ✕ → popup closes, isOpen=false saved, focus returns to page button
Navigate to another horoscope → pending payload flushed (keepalive, old id)
  → new horoscope's notepad state applies (own geometry/isOpen/selection)
Refresh → nothing lost (keepalive flush on beforeunload)
Return to horoscope → restore: geometry + selection + all tags/notes
```

### Flow 4 — Failure path

```
Edit tag color → optimistic update → PUT fails (network/5xx)
  → local state rolled back to last server-confirmed value
  → toast notepad.toast.saveFailed (z-50, above popup) → auto-clear 3s
  → student retries the same edit (no data loss, no silent divergence)
```

## Accessibility

- **Popup**: `role="dialog"`, `aria-modal="false"` (non-modal — the page stays reachable behind it), `aria-label` = notepad title. Focus on open → first parent chip; on close → returns to the page entry button. `Escape` closes (non-trapped focus, so Escape applies while focus is inside the popup only).
- **Chips (parent/sub-tag)**: `role="group"` + `aria-pressed` toggle buttons (single-select; matches existing chip conventions — tablist semantics do not apply since these are toggles, not tabs), roving tabindex, arrow keys, `Home`/`End`. Clicking the selected chip = no-op (no announcement churn).
- **Color is never the only channel**: system chips carry the leading `●` dot + tint + `aria-label` classification word (good/bad/neutral); student chips are distinguished by shape (dashed square) + edit/delete affordances, not color alone. The ratio badge has a localized `aria-label` (`3 of 5 good`).
- **Drag/resize**: pointer events (mouse/touch/pen) with `touch-action: none`; keyboard alternative = `Ctrl+Alt+Arrows` (nudge 8px) / `Ctrl+Alt+Shift+Arrows` (resize 16px) + "Reset position" button. Plain `Alt+Arrow` avoided (browser back/forward conflict).
- **Touch targets**: header drag handle ≥ 44px; corner resize zone 16px visual but padded hit area ≥ 24px on mobile; chips ≥ 32px with 4px gaps.
- **Screen reader flow**: button → dialog → parent strip → sub-tag strip → observations region (`aria-label` = `notepad.aria.observationsRegion`) → student tags → result notes; ratio badges announced via `aria-label`, not raw `(3/4)`.
- **Live regions**: save-failure toast uses the existing toast live-region behavior; optimistic chip adds/removals announce via polite `aria-live` on the student-tags list only (system sections re-derive silently).

---

## Responsive Behavior

- **Desktop (≥ 1024px)**: popup floats over the right side (right-docked default), drag anywhere, full label on the page button.
- **Tablet (640–1023px)**: identical behavior; clamps keep the popup on-screen; sub-tag rows wrap into more rows.
- **Mobile (< 640px)**: button collapses to icon-only (with content dot); popup width = `min(480, vw − 16)` — the viewport clamp wins over the 320px min on very narrow screens; touch drag via the 44px header; corner resize via touch (pointer events unify mouse/touch); **no full-screen takeover, no separate mobile layout**; Sinhala labels wrap via chip-wrap (allow up to ~30% wider Sinhala text — the strip wraps whole chips, so no clipping and no horizontal scroll, per the mobile-table-layouts convention).

## Micro-interactions

- Open/close: 150ms fade + 8px translate; shared by the page button and header `✕`.
- Drag/resize: 1:1 pointer tracking, no transition, `will-change: left/top` during drag; commit on pointer-up.
- Chip select: 100ms color transition to the indigo active fill.
- New student tag: 150ms fade-in; composer clears and refocuses the input (rapid capture loop).
- Ratio badge: instant number swap (no animation needed).
- Save success: silent (no toast — ShadBala precedent). Save failure: toast (z-50, above popup), auto-clear 3s.
- Horoscope switch: instant content swap; optional 100ms fade on the observations region only.
- Content dot on the page button: fades in 150ms after first saved tag/note.
