## Overview

The Bhava Suchika (භාව සුචික, "house index") is a Vedic study value (1–12) telling which house of the birth (Lagna/D1) chart the Navamsa (D9) sign of a point falls in:

```
Bhava Suchika = ((navamsaSign − lagnaSign) mod 12) + 1
```

The Lagna value uses the D9 first-house sign; each of the 9 planets (incl. Rahu/Ketu) gets its own value from its Navamsa sign. Every value has a named form in both locales (e.g. value 7 = සප්තමාංශකය / Saptamamshaka) — the names are the study vocabulary, the number is the scanable index.

**UX goals:**
1. Make the value scannable at a glance (number first), then learnable (named form + explanation tooltip).
2. Render identically on every view (own / public / share link) — display-only, no overrides.
3. Never leave a gap or crash on legacy or manual-without-Navamsa charts — fall back or show the table's standard `—` empty convention.
4. Bilingual end-to-end: no hardcoded strings; names resolve from the numeric value via i18n at render time (same pattern as planet/sign names).

**Precedent followed:** the Lagna-section tag reuses the ascendant flag pill pattern (`page.tsx:1245-1310`); the planets-table column follows the existing column/cell styling of the Nakshatra column (`page.tsx:1484-1486`, `:1640-1643`); the legacy render-time fallback mirrors `resolvedMaranakaraka` / `resolvedYogakaraka` / `resolvedShadbalaya` (`page.tsx:371-380`, `:512-526`); the tooltip reuses the AspectTooltip pattern.

## Answers to the Architect's routed UX open questions (OQ4 / OQ5)

### OQ4a — Column placement and cell format

**Decision: new column after Nakshatra; cell format `{value} — {name}`; blank `—`.**

- **Position:** the column is inserted immediately after the Nakshatra (Pada) column — between Nakshatra and Conjunctions — at all three render sites:
  - Desktop/tablet table: `<th>` after the Nakshatra header (`page.tsx:1484-1486`), `<td>` after the Nakshatra cell (`page.tsx:1640-1643`).
  - Mobile card: `<span>` after the Nakshatra span (`page.tsx:1839-1841`).
  - Rationale: per the product owner's explicit requirement — the Bhava Suchika column must follow the Nakshatra column. The value is thus grouped with the other per-planet quality columns (sign, strength, house, navamsa, navamsa strength, nakshatra) and sits before the conjunction/aspect relationship columns.
- **Cell format:** `{value} — {name}` (number, spaced em dash U+2014, name), e.g. `7 — සප්තමාංශකය` / `7 — Saptamamshaka`. Western numerals in both locales (the rest of the table uses Western numerals in SI, e.g. the House column). This satisfies US-BS-002 AC2 exactly.
- **Blank cell:** `—` (em dash) — the table's existing empty-cell convention (see Conjunctions/Aspects/Other/Navamsa cells at `page.tsx:1644-1660`, `:1680`), and the architect's specified `\u2014` fallback. Used for manual charts without entered Navamsa data and for corrupt/out-of-range stored values.
- **Width behavior:** the value cell is `whitespace-nowrap` (the Sinhala names are long, e.g. පූර්වපුන්‍යාංශකය, and must not break mid-name); the desktop table already scrolls inside `overflow-x-auto`, so the column width is absorbed without layout shift.

### OQ4b — Lagna-section tag style

**Decision: first tag in the existing ascendant tag row; same pill geometry as the flags; indigo treatment; label + value + name; the tag itself is the tooltip trigger.**

- **Position:** first (leftmost) in the tag row rendered by the ascTags IIFE (`page.tsx:1294-1309`). Rationale: it is the only *always-present* element of the row when computable (the flags are conditional), so it anchors the group; the four conditional flags keep their existing relative order (zero regression risk); and this feature's headline value gets the primary position.
- **Visual:** same pill geometry as the flags — `inline-flex items-center gap-1 text-xs rounded px-2 py-0.5 border` — with the indigo treatment already used for the Wargoththama tag (`text-indigo-700 bg-indigo-50 border-indigo-200`), since like Wargoththama it is a primary derived value rather than a condition flag. Never strikethrough (strikethrough is reserved for crossed Wargoththama).
- **Content:** `{label}: {value} — {name}`, e.g. `භාව සුචික: 7 — සප්තමාංශකය` / `Bhava Suchika: 7 — Saptamamshaka` (US-BS-001 AC1 + AC2). The label prefix is required — it is what makes the tag self-identifying next to the four flag tags.
- **Interactivity:** the tag is wrapped in a `<button type="button">` (pill styling preserved) so it is keyboard-focusable and is the tooltip trigger (hover / focus / tap). Accessible name = its visible text; no extra aria needed.

### OQ5 — Search-page mirroring

**Decision: REVISED per product owner — YES, mirror Bhava Suchika onto the search result cards.** (2026-08-14: search integration is now in scope — US-BS-008.)

- **Lagna block:** the search card Lagna block (`src/app/search/page.tsx:775-830`) already mirrors the four flag tags via `computeAscendantSpecialFlags`; it now gains the Bhava Suchika tag in the same format as the detail page (`{label}: {value} — {name}`, indigo pill, first in the tag row).
- **Planet rows:** each planet row on the search card shows `{value} — {name}` in the same position as the calculation tab (after Nakshatra). Manual charts without Navamsa data omit both (blank `—` / no tag).
- **Search queries:** students can query by the Lagna value (`"භාව සුචික ලග්නාංශකය"`, `"bhava suchika bhagyamshaka"`, `"ලග්නාංශකය"`, `"bhava suchika 9"`) or by a specific planet's value (`"ගුරු භාව සුචික 11"`), using the same grammar as the rest of search. Matching reuses the existing keyword/exact/vector pipeline — no new search UI.
- The calculation-tab display stays the canonical home; the search card is the compact mirror (consistent with how the flags are mirrored today).

- **Purpose:** the student sees the Lagna's Bhava Suchika alongside the existing ascendant flags (Wargoththama, Gandanta/Gandamula, Pushkara).
- **Elements:** the existing section header (ලග්නය / Ascendant), the Lagna line (sign, degree, nakshatra + pada), the tag row (`flex flex-wrap gap-2`), and the new first tag.

## Component Design

| Component | Purpose | States | Props / data |
| --------- | ------- | ------ | ------------ |
| `BhavaSuchikaTag` (Lagna section pill, button-wrapped) | Show the Lagna's house index with label + named form; tooltip trigger | `value` (1–12) · hidden (manual w/o Navamsa) · hover/focus (tooltip open) | `value: number`, `label: string` (t key), `name: string` (t key), `tooltip: string` |
| `BhavaSuchikaCell` (desktop `<td>` + mobile `<span>`) | Show a planet's house index with named form, or `—` | `value` (1–12) · blank (`—`) · out-of-range (`—` + warn) | `value?: number`, `name?: string` |
| `BhavaSuchikaHeader` (desktop `<th>`) | Column header label + `ⓘ` tooltip anchor | default · hover/focus (tooltip open) | `label: string`, `infoGlyphAria: string`, `tooltip: string` |
| `BhavaSuchikaTooltip` | Bilingual explanation of the method | closed · open | `text: string`; reuses AspectTooltip pattern + `title` fallback |
| `resolvedLagnaBhavaSuchika` / `resolvedBhavaSuchika` (render-time resolution) | stored value ?? pure-function fallback, gated per source | — | mirrors `resolvedMaranakaraka`/`resolvedShadbalaya` (`page.tsx:371-380`, `:512-526`); gate: fallback never fires for manual charts without entered Navamsa data |

**Data flow (display-only):** `calculatedDetails.lagnaBhavaSuchika` / `calculatedDetails.bhavaSuchika["1"…"9"]` → render. No mutation, no override UI, no POST/PUT. Recalculation (full recalculation job only) rewrites the stored values; legacy docs resolve at render time.

## Accessibility

- **Keyboard:** the Lagna tag (as a `<button>`) and the header `ⓘ` glyph are tabbable; tooltips open on focus (and close on blur), matching the AspectTooltip pattern; `title` attribute carries the same text as a fallback.
- **Screen readers:** the tag's accessible name is its full text (`භාව සුචික: 7 — සප්තමාංශකය`); the header `ⓘ` has `aria-label` from `infoGlyph`; the mobile span is plain text read in row context (planet name precedes it in the button's accessible name) — no additional aria needed.
- **Color contrast:** indigo pill (`text-indigo-700` on `bg-indigo-50`) and `text-gray-600` span values both pass on white — unchanged from existing tags/cells.
- **Reduced motion:** tooltips use fade only (no slide), consistent with existing tooltips.

## Responsive Behavior

- **Desktop/tablet (≥ 640px):** 11-column table inside the existing `overflow-x-auto` container; new column after Nakshatra; header `ⓘ` visible.
- **Mobile (< 640px):** planet rows are cards; the new span renders after the Nakshatra span in the card header; the header button gains `flex-wrap` so the wider header wraps gracefully (tags already wrap); `ⓘ` glyph is hidden in the header (no table header exists on mobile) — the mobile span is the tooltip trigger instead.

## Micro-interactions

- **Tooltip:** fade-in ~120ms on hover/focus/tap; closes on pointer-leave/blur/Escape; `title` fallback for no-JS/print. No animation on the tag/cell content itself (value is static text).
- **No other motion:** the tag and column are static content; no loading shimmer, no reorder animation (the tag is always first, flags keep their order).
