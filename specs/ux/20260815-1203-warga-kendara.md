## Overview

The Warga Kendara (වර්ග කේනදර) feature replaces the horoscope detail page's fixed "Birth & Navamsa" chart pair with a **varga tab strip**: the Rāśi (D1) chart is permanently pinned as the first chart, and the student selects a second chart among Navāṁśa (D9, default), Surya Lagna and Chandra Lagna. Each displayed chart gains its **main indication shown as tag chips** directly beneath the chart caption, plus its own Houses + Planets tables directly beneath the figure. The whole surface is display-only (own view, public view, and share links render identically), fully bilingual, and derived purely from stored `CalculatedDetails.wargaKendara` data with a render-time fallback for legacy documents.

**UX goals:**

- **Study-first comparison** — pin the D1 chart as the stable reference while the second chart swaps, so the student can compare any warga against the birth chart without losing context.
- **Zero dead ends** — clicking the pinned D1 or the already-selected second chart is a no-op; every chart is self-describing through its own indication tags (no separate reference table).
- **Progressive disclosure** — charts first, indication tags beneath each caption, per-chart tables beneath the figure.
- **Bilingual parity** — every label, caption, marker, and tooltip resolves via i18n (EN/SI); no hardcoded strings.
- **Consistency with existing conventions** — reuse the chart-pair grid, flag-pill styling, `aria-pressed` button pattern, `—` empty-cell convention, mobile stacked-card tables (< 640px), and the `noChartData` placeholder.

## Answers to the design questions

### Q1 — Tab strip + two-chart selection (layout, states, click behavior)

The Charts tab section header becomes the varga tab strip. It is **not** a `role="tablist"` — tablist semantics allow exactly one selected tab, but this UI has two simultaneous selections (D1 pinned + second chart). Instead it is a labeled `role="group"` of toggle buttons with `aria-pressed`, matching the existing "Other Charts" buttons pattern (`page.tsx:1157`). D1 renders as a pinned **non-interactive badge** (a `<span>`, `tabindex="-1"`) so "clicking D1 = no-op" holds by construction.

| Element | State | Visual | Behavior |
|---------|-------|--------|----------|
| D1 badge | pinned (always) | selected-pill treatment (`bg-indigo-600 text-white`) + 16px lock glyph (inline SVG, `aria-hidden`) | Not a button; not focusable; click/tap does nothing |
| Second-chart button | unselected | outline pill (`border text-gray-600`) | Click → becomes second chart (150ms crossfade) |
| Second-chart button | selected | selected-pill treatment (`bg-indigo-600 text-white`) | Click → no-op (already shown) |
| Second-chart button | hover/focus | `bg-gray-50` + visible focus ring (same as existing tab buttons) | — |
| Strip (mobile) | — | horizontally scrollable (`overflow-x-auto`, no scrollbar) | Touch swipe; `aria-orientation` not needed since it is a button group |

Tab labels (bilingual, `astrology.wargaKendara.tabs.*`): `රාශි (D1)` / `Rāśi (D1)`, `නවාංශක (D9)` / `Navāṁśa (D9)`, `සූර්ය ලග්න` / `Surya Lagna`, `චන්ද්ර ලග්න` / `Chandra Lagna`. Section title above the strip: `වර්ග කේනදර` / `Warga Kendara` (replaces the `chartPairTitle` "Birth & Navamsa" usage on this page).

The "Other Charts" section is reduced to **House only** (US-WK-006).

### Q2 — Main indication as tags after each chart (no separate reference table)

The 16-varga "Varga Reference" table is **not rendered** (product decision 2026-08-15: "No need Warga Wimarshanaya"). Instead, **each displayed chart shows its main indication as tag chips directly beneath the chart caption**, inside the same figure card, above the Houses table:

- **D1** → tags from D1's main indication, e.g. "Overall life" · "Body" · "General circumstances" (සමස්ත ජීවිතය · ශරීරය · පොදු තත්ත්ව).
- **D9** → "Marriage" · "Dharma" · "Strength of planets" (විවාහය · ධර්මය · ග්රහ බලය).
- **Surya Lagna / Chandra Lagna** → their own indication tags (provisional: "Sun-based chart" / "Moon-based chart" — pending domain confirmation).

**Tag rendering rule:** the indication string from the static varga catalog (`astrology.wargaKendara.vargas.*.{name|indication}`, i18n-resolved per locale) is split on `,`/`;` into individual tag chips (`text-xs` pills, same styling as the `Other`-column chips). An indication with no comma renders as a single tag. This reuses the existing flag-pill pattern — no new visual language.

Rationale: the pair already names the four phase-1 charts in the strip; attaching the indication to each chart makes the comparison self-describing and removes a whole separate surface. D2–D60 do not appear anywhere in phase 1 (they are not tabs, not a table).

### Q3 — Per-chart tables placement

Each displayed chart figure gets a **per-chart table card directly beneath the figure inside the same white card**, with the chart's main indication tags directly beneath the caption (Q2):

- **Houses table**: `#` | `Sign` | `Planets` | `Aspects` — 12 rows, whole-sign houses for that chart.
- **Planets table**: `Planet` | `Sign` | `Str` | `House` | `Conjunctions` | `Aspects` | `Other`.

**D1-only columns:** Nakshatra (Pada) and Bhava Suchika render **only on the D1 Planets table** — on D9/Surya Lagna/Chandra Lagna tables these columns are **omitted entirely** (never rendered as empty columns). This matches the data model (only the `d1` entry carries `nakshatra`/`pada`; Bhava Suchika reads the existing top-level fields).

**Conjunctions/Aspects** render without degree differences — planet chips with the existing AspectChip styling and hover tooltip, but no inline degree/delta text (the data model stores no degree fields on these rows).

**`Other` cell contents:**
- **D1**: the 12 D1-only flags — Wargoththama, Pushkara, Gandantha, Gandamula, 64th Navamsa Lord, 22nd Drekkana Lord, Cheshta Bala, Ashtamansha, Kala Bala, Atmakaraka, Combust, Badhaka — rendered as compact `text-xs` chips (reusing the existing flag-pill styling and existing `astrology.*Label` keys).
- **Every chart (incl. D1)**: Maraka, Maranakaraka, Dig Bala appended to the chips (existing `astrology.marakaLabel` / `maranakarakaLabel` / `digBalaLabel`).
- Empty arrays → cell shows `—` (existing empty-cell convention).

The existing Calculations tab Planets/Houses tables remain unchanged (the Charts-tab D1 tables are the warga-specific rendering; the Calculations tab keeps its current layout including the Bhava Suchika column added in the previous rev).

### Q4 — D2–D60 rendering: **omitted entirely in phase 1** (no disabled tabs, no reference table)

**Recommendation: no disabled tabs and no reference table.** Four tabs only; D2–D60 do not appear in the Charts tab at all in phase 1. Rationale:

- 14 disabled tabs would dominate the primary interaction and imply the data exists.
- Each displayed chart already carries its main indication as tags (Q2) — the study context is per-chart, not a roadmap table.
- When a later phase adds computation for D2–D60, the strip grows incrementally (same component, new entries in the tab config), and each new chart brings its own indication tags automatically.

### Q5 — No-data states

| Scenario | Behavior |
|----------|----------|
| Auto horoscope | All four phase-1 charts computable; tables always populated |
| Manual horoscope, D1 | Always populated (derives from entered `manualHousePlacements`) |
| Manual horoscope, D9 without entered Navamsa data | Second slot renders the existing `astrology.noChartData` placeholder ("සටහන් දත්ත නොමැත") — same treatment as today's empty navamsa pair slot; the D9 tab remains selectable, selecting it shows the placeholder |
| Manual horoscope, Surya/Chandra Lagna | Always populated (rotation of the entered chart to Sun/Moon lagna) |
| Legacy document (no `wargaKendara` field) | Render-time pure-function derivation (`resolveWargaKendara`) — first paint populated, no flicker (same pattern as Shad Bala/Bhava Suchika legacy fallback) |
| Empty arrays (e.g. no conjunctions, no maraka planets) | Cell shows `—` |

### Q6 — Accessibility

- **Strip**: `role="group"` with `aria-label` = "Select second chart" / "දෙවන සටහන තෝරන්න"; buttons carry `aria-pressed`; D1 badge is a `<span>` with the lock glyph `aria-hidden` and an `aria-label` on the badge ("Rāśi (D1) — always shown" / "රාශි (D1) — සැමවිටම පෙන්වයි") for screen readers; roving tabindex within the group; arrow keys move between buttons; Home/End jump to first/last; Space/Enter toggles; focus ring visible on all buttons; 40px touch targets.
- **Tables**: real `<table>` with `<caption>` (composed from `astrology.chartCaptions.*` + `astrology.houses`/`astrology.planets`), `<thead>` with `<th scope="col">`, first column cells as `<th scope="row">`; mobile card layout is a `role="list"` of labeled cards (`role="listitem"`, each with an `aria-label` that is the full row text).
- **Indication tags**: a labelled group (`aria-label` = `astrology.wargaKendara.indicationLabel`, e.g. "Main indication"); the chips themselves are decorative text (no interactive role); an unresolvable indication renders the em-dash `—`.
- **Contrast**: indication chips use the existing tag palette (≥ 4.5:1 against `--surface`); selected pill `bg-indigo-600 text-white` meets AA; no color-only markers anywhere.
- **Screen-reader announcements**: chart swap announces the new chart name (existing `aria-live="polite"` region around the chart pair, or button `aria-label` change); no toast needed (no data mutation).

## User Flows

### Flow 1 — View warga charts (default)

```
Student opens horoscope detail → Charts tab (default) 
  → Strip shows: [🔒 රාශි (D1)] [නවාංශක (D9)✓] [සූර්ය ලග්න] [චන්ද්ර ලග්න]
  → Grid shows two figures: D1 (left) + D9 (right)
  → Beneath each caption: main indication tags (e.g. D1: සමස්ත ජීවිතය · ශරීරය · පොදු තත්ත්ව)
  → Beneath each figure: Houses table, then Planets table
```

### Flow 2 — Swap the second chart

```
Student clicks [සූර්ය ලග්න]
  → aria-pressed moves: D9 off, සූර්ය ලග්න on
  → Right figure crossfades (150ms) to the Surya Lagna chart
  → Indication tags + per-chart tables swap to the Surya Lagna data (no Nakshatra/Bhava Suchika columns)
  → Student clicks [සූර්ය ලග්න] again → no-op (already shown)
  → Student clicks [🔒 රාශි (D1)] → no-op (badge, not a button)
```

### Flow 4 — Manual horoscope without Navamsa data

```
Student opens manual horoscope (no navamsa entered) → Charts tab
  → D1 chart renders; second slot shows "සටහන් දත්ත නොමැත" placeholder
  → D9 tab selectable; selecting it keeps the placeholder in the second slot
```

### Flow 5 — Share link / public view

```
Visitor opens public horoscope or share link → Charts tab identical
  → Strip, charts, indication tags, per-chart tables all render read-only
  → No editing affordances anywhere (no overrides exist for this feature)
```

## Component Design

| Component | Purpose | States | Props |
| --------- | ------- | ------ | ----- |
| `WargaKendaraSection` | Charts-tab section wrapper: title + strip + chart pair + Other Charts | default | `horoscope`, `session`, `locale` |
| `WargaTabStrip` | Pinned D1 badge + second-chart toggle buttons | pinned (D1), selected, unselected, hover, focus | `secondChart: WargaChartKey`, `onSelectSecond(key)`, `tabs: WargaTab[]` (phase 1: 4 entries) |
| `WargaChartPair` | Two-slot grid (`grid grid-cols-1 lg:grid-cols-2 gap-4`) with crossfade | swapping (150ms), idle | `first: WargaChartData`, `second: WargaChartData`, `secondKey` |
| `WargaChartFigure` | One figure card: caption + indication tags + SVG + Houses table + Planets table | populated, no-data (placeholder slot) | `chartKey`, `caption`, `indicationTags: string[]`, `chartData` (SVG source), `lagnaSign`, `source` |
| `WargaIndicationTags` | Main-indication chip row for one chart figure | populated (≥1 chip), empty (`—`) | `tags: string[]` (i18n-resolved, comma-split) |
| `WargaHousesTable` | Houses table / mobile cards | populated, empty rows (`—`) | `houses`, `lagnaSign`, `caption`, `chartKey` |
| `WargaPlanetsTable` | Planets table / mobile cards | populated, empty arrays (`—`) | `planets`, `isD1`, `bhavaSuchika?`, `flags` (D1: 12 arrays/values; all: maraka/maranakaraka/digBala), `caption`, `chartKey` |
| `OtherCell` | Chips renderer for the `Other` column | populated, empty (`—`) | `items: { label: string, present: boolean }[]` — D1 passes 12+3 items, other charts pass 3 |
| `WargaLockGlyph` | 16px inline SVG lock for the D1 badge | static | `aria-hidden` (decorative) |

**Data flow:** `CalculatedDetails.wargaKendara` (or render-time `resolveWargaKendara` fallback for legacy docs) → `wargaKendara[d1 | d9 | suryaLagna | chandraLagna]` → `WargaChartPair`/`WargaChartFigure`. No API calls, no mutation endpoints, no loading spinners (data ships with the page render).

## States

| State | Trigger | UI |
|-------|---------|-----|
| Default | Page load, auto horoscope | Strip: D1 pinned + D9 selected; two populated figures with indication tags + tables |
| Second-chart swap | Student selects a different tab | 150ms crossfade on the right figure + tags + tables; `aria-pressed` moves |
| No-op click | Student clicks pinned D1 or selected second tab | Nothing changes (D1 not a button; selected button ignores activation) |
| No-data | Manual horoscope, D9 selected, no navamsa entered | Second slot shows `noChartData` placeholder; D1 figure + tags + tables unaffected |
| Legacy | Document without `wargaKendara` | Render-time derivation — identical UI, no loading/flicker |
| Mobile | < 640px | Strip scrolls horizontally; figures stack; tables become stacked cards |
| Error | — | Not applicable (pure derived data, no API); any unexpected absence degrades to the `noChartData` placeholder |

## Accessibility

- **Keyboard navigation**: Tab moves into the strip group (roving tabindex — one button in the tab order); Left/Right arrows move between buttons; Home/End jump to first/last; Space/Enter activates; D1 badge is not in the tab order; tables are natively navigable; mobile cards are a `role="list"`.
- **Screen readers**: strip `role="group"` + `aria-label`; buttons announce label + pressed state (`aria-pressed`); D1 badge announces "Rāśi (D1) — always shown"; figure captions use the existing caption pattern; indication tags row carries the `astrology.wargaKendara.indicationLabel` aria-label (e.g. "Main indication: Overall life, Body, General circumstances") and the chips themselves are decorative; tables use `<caption>` + `scope`; empty cells announce as `—` (em dash, consistent with the rest of the app); swap announcements via the existing `aria-live="polite"` chart-pair region.
- **Contrast**: selected pill `bg-indigo-600 text-white`; focus ring visible (indigo 2px offset) on all interactive elements; indication chips use the existing tag contrast (≥ 4.5:1).
- **Touch targets**: strip buttons ≥ 40px (44px preferred) tap area on mobile; mobile planet/house cards are fully tappable for tooltips where applicable.

## Responsive Behavior

| Breakpoint | Strip | Chart pair | Per-chart tables | Indication tags |
|------------|-------|-----------|------------------|-----------------|
| Desktop > 1024px | Single row, left-aligned, 4 tabs | `grid-cols-2` side-by-side figures | Full-width table under each figure (Houses then Planets) | Chip row under each caption, wraps to next line |
| Tablet 640–1024px | Single row (may scroll if SI labels wide) | `grid-cols-1` stacked (existing `lg:` behavior) | `sm:block` tables | Chip row, wraps |
| Mobile < 640px | `overflow-x-auto`, swipeable | Stacked | Card-per-house + card-per-planet (per `20260717-1400` convention), no horizontal scroll | Chips wrap; no horizontal scroll |

**Sinhala considerations:** tab labels and indications are 15–20% wider — allow the strip to scroll on narrow viewports instead of shrinking pills; reference indication column gets no `max-width` truncation on desktop (wraps); mobile cards wrap freely.

## Micro-interactions

- **Chart swap**: 150ms opacity crossfade on the second figure card (existing chart-pair region); no slide (keeps the D1 reference stable in place).
- **Tab press**: `transition-colors` 100ms on the pill (outline → indigo fill).
- **Indication tags**: static chips (no animation); the caption crossfades with the figure on swap.
- **Lock glyph**: static; no animation (deliberate — communicates permanence).
- **No toasts** — the feature mutates nothing.
