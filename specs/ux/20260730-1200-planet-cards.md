## Overview

The planets (ග්‍රහයෝ) section in the horoscope detail view currently renders an 8-column `<table>` with all data visible at once. This creates problems:

1. **Too many columns** — conjunctions, aspects, and tags columns contain long text that wraps awkwardly
2. **Poor scannability** — finding a specific planet's key data (sign, strength, house) requires scanning across many columns
3. **Horizontal scroll** — on viewports < 900px, the table overflows
4. **No information hierarchy** — "Conjunctions" and "Aspects" are secondary data that crowd out the core 5 fields

This spec replaces the table with individual **planet cards** — compact summary rows with an optional expandable detail panel — at all viewport widths.

### Design Goals

1. **Essential-first** — ග්‍රහයා, රාශිය (අංශකය), බලය, භාවය, නැකත (පාදය) are always visible in a single horizontal strip
2. **Progressive disclosure** — conjunctions, aspects, retrograde, combustion, special lords, navamsa hidden behind a tap-to-expand
3. **Responsive by default** — card layout works naturally at any width without horizontal scroll
4. **Retrograde at a glance** — retrograde planets have a clear visual marker (icon/badge) on the card, not hidden in the name formatting
5. **Consistent with DashaSection** — uses the same Set-based expand pattern already established in `DashaSection.tsx`

```
┌────────────────────────────────────────────────────────────────────────┐
│  ☉ රවි    ♈ මේෂ (23:15:40)    උච්ච    භාව 1    රේවතී (3)      ▶   │
└────────────────────────────────────────────────────────────────────────┘

│  ☿ බුධ    ♊ මිථුන (12:30:00)    මිත්‍ර    භාව 3    ආද්‍රා (2)   වක්‍ර ▶  │
└────────────────────────────────────────────────────────────────────────┘
```

Each collapsed card is a single horizontal bar containing:

| # | Field | Content | Notes |
|---|-------|---------|-------|
| 1 | Planet icon + name | `☉ රවි` | Sun glyph + localized name |
| 2 | Sign + degree | `♈ මේෂ (23:15:40)` | Sign glyph + name + degree in parens |
| 3 | Strength | `උච්ච` | Compact strength label (bold if exalted/debilitated) |
| 4 | House | `භාව 1` | "භාව" prefix + number |
| 5 | Nakshatra + pada | `රේවතී (3)` | Nakshatra name + pada number in parens |
| 6 | Expand chevron | `▶` / `▼` | Toggle icon on the right |

**Retrograde indicator:** If the planet is retrograde (and not Rahu/Ketu), append a small `වක්‍ර` badge/tag after the planet name, styled in a muted color (e.g. `text-amber-600 bg-amber-50 text-xs rounded px-1`).

**Color coding (strength):**

| අති උච්ච / උච්ච | `text-green-700 font-semibold` |

```
│  අස්ථ  ·  64 න.ධි  ·  ආත්මකාරක  ·  මාරක                            │

```

The expanded panel reveals below the summary row:

| Section | Content | Source |
|---------|---------|--------|
| **සංයෝග** (Conjunctions) | Comma-separated list of `PlanetName (±DD:MM:SS)` | Planet orb calculation |
| **දෘෂ්ටි** (Aspects) | Comma-separated list of `PlanetName (±DD:MM:SS)` | Planet aspects array |
| **Special tags** | Badges: අස්ථ (combust), 22 දෙ.ධි (22nd Drekkana Lord), 64 න.ධි (64th Navamsa Lord), ආත්මකාරක, මාරක, බාධක | `calculatedDetails` fields |
| **නවාංශක (D9)** | Sign name (strength) | `p.navamsaSign`, `p.navamsaStrength` |

Empty sections (e.g. no conjunctions, no aspects, no special tags) are omitted entirely from the expanded panel — no "—" placeholder needed.

### Transition Behavior

- **Expand:** The detail panel slides open with a `max-h` CSS transition (matching the pattern in `DashaSection.tsx`)
- **Collapse:** Slides closed, returning to the compact card
- **Default state:** All cards begin collapsed. Only `expandedPlanets` state drives visibility.

### Multiple Expands

Users can expand multiple cards simultaneously. This is important for comparison (e.g. checking conjunctions across planets). No accordion-style single-open constraint.

## Interaction States

| State | Visual | Behavior |
|-------|--------|----------|
| Default (collapsed) | Compact card, `▶` chevron, cursor pointer | Click anywhere on card to expand |
| Hover (collapsed) | `bg-gray-50` background tint | Indicates clickability |
| Expanded | Card with detail panel, `▼` chevron | Detail panel visible below summary |
| Hover (expanded) | `bg-gray-50` on summary row only | Indicates click-to-collapse |

---

## Responsive Behavior

Since the card layout is inherently responsive, no breakpoint-specific changes are needed:

| Viewport | Behavior |
|----------|----------|
| >= 640px | Cards at full width, fields in a horizontal flex row |
| < 640px | Cards at full width, fields may wrap to 2 lines if needed (planet name + sign/degree on top row, strength + house + nakshatra on bottom row) |

On narrow screens (< 480px), the strength label can be abbreviated using existing short keys (e.g. "උච්ච" stays, others remain as-is since Sinhala terms are already short).

| Aspect | Current Table | Card Design |
|--------|--------------|-------------|

## Implementation Notes

### State
The `expandedPlanets` state is already declared at `src/app/horoscopes/[id]/page.tsx:106`:
```typescript
const [expandedPlanets, setExpandedPlanets] = useState<Set<number>>(new Set());
```
This needs to be wired to the planet card toggle — no new state required.

### Toggle handler
```typescript
const togglePlanetExpand = useCallback((planetName: number) => {
    setExpandedPlanets((prev) => {
        const next = new Set(prev);
        if (next.has(planetName)) {
            next.delete(planetName);
        } else {
            next.add(planetName);
        }
        return next;
    });
}, []);
```
Key by `p.name` (Planet enum value) since each planet appears once.

### Navamsa display
The `Planet` interface already carries `navamsaSign` and `navamsaStrength` — these are computed in `calculation.ts` but never displayed. The expand panel should show them.

### Retrograde badge style
```html
{p.retrograde && p.name !== 8 && p.name !== 9 && (
    <span className="text-amber-600 bg-amber-50 text-xs rounded px-1 ml-1">
        {t("astrology.retrograde")}
    </span>
)}
```

### Same treatment for search page
The identical table in `src/app/search/page.tsx` (lines 876-995) should receive the same card treatment for consistency. The compact `PlanetPositionsTable` (lines 239-297) can remain as-is since it's intentionally compact for search result previews.

## Accessibility

- Card is a `<button>` or has `role="button"` + `tabindex="0"` for keyboard access
- Expand/collapse uses `aria-expanded` on the toggle
- Chevron icon uses `aria-hidden="true"`
- Color is not the only means of conveying strength — strength text label is always present
